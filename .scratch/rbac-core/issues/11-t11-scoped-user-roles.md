# T11：在部门范围内分配人员角色并拒绝越权

**类型：**后端业务闭环\
**范围：**当前 RBAC 后端整改\
**Status:** awaiting-manual-claim\
**平台发布：**待发布；暂无 GitHub Issue 编号。\
**负责人：**待组员认领；本文件不会触发自动领取或实现。

## What to build

有对应权限的部门管理者能为本部门及下级人员配置角色，保存后影响其真实 API 访问；超范围、自提权或非法人员变更被拒绝。

## Blocked by

- [T05](./05-t05-identity-query-authorization.md)
- [T10](./10-t10-user-role-review.md)

**阻塞原因：**需要真实鉴权/人员范围和对应契约；可分配已确认的初始化角色，不必等待 T09 的角色编辑接口。

## Acceptance criteria

- [ ] 按 T10 契约用 JPA 查看当前角色、计算可分配角色并整体保存/撤销；写入全部成功或回滚。
- [ ] 逐请求校验具体操作权限及目标人员部门；同级其他部门拒绝，不信任前端提供的范围或角色候选列表。
- [ ] 不能授予超出自身有效权限的角色；部门管理员不能修改全局管理员，也不能改自己的授权或所属部门。已确认的调部门操作同时检查原、目标部门。
- [ ] 人员停用及角色分配/撤回影响后续真实请求；无管理权限仍不影响有效账号登录，不引入独立登录资格。
- [ ] 本票的撤权、人员状态/归属变更覆盖最后有效管理员保护；事务内检查与锁一致，并发不能造成管理员全部失效。
- [ ] 逐项迁移可明确对应的旧人员角色分配，旧独立范围不照搬；同步清理本切片 JDBC、调用、初始化、测试、配置和文档，提供真实 HTTP 防越权与授权变化证据。

## 共享模块及冲突

人员/角色关联、候选角色、部门范围、用户状态、授权失效与管理员保护。与 T03/T09 共享人员数据和权限计算，与 T07 共享保护路径，需要同步接口和锁约定。

## 开始与完成

- 开始前阅读[整改执行入口](../../../docs/rbac-rectification/RBAC整改执行入口.md)，逐项核对本票阻塞项和评审证据。
- 只执行用户指定的本票；在独立分支或工作树修改，保护已有未跟踪文档。
- 验收项是未来完成条件，全部保持未勾选；拆票获批不等于设计评审或运行验收通过。
- 按交付类型保留原型/契约评审、数据库/HTTP/并发等相应证据；记录实际未验证项。正式前端仍暂缓。
- 提交本票变更供小组评审；前置票的结论与所需产物进入共同基线后，下游才可开始。不得自行合并或顺带认领下游。
