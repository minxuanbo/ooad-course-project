**类型：**原型与契约前置\
**范围：**当前 RBAC 后端整改\
**Status:** awaiting-manual-claim\
**平台发布：**已发布：[Issue #5](https://github.com/minxuanbo/ooad-course-project/issues/5)。\

## What to build

用可讨论的原型走通有效账号进入系统、无管理权限提示、按部门找人和分页搜索，并把每个场景转为已审核的接口契约。

## Blocked by

- [T01 / #2](https://github.com/minxuanbo/ooad-course-project/issues/2)（[本地镜像](./01-t01-model-review.md)）

**阻塞原因：**需要稳定的身份、管理范围和用户模型；不必等待数据库导入完成。

## Acceptance criteria

- [ ] 原型展示有效账号可登录；无管理权限时显示提示，能查询本人身份/权限，不以管理权限决定登录资格。
- [ ] 覆盖本部门/下级导航、同级越界、搜索与筛选组合、分页总数、空结果、错误和无权状态；不能一次呈现全部人员。
- [ ] 明确每个场景的请求方法、路径、字段、响应、错误、分页约定、权限条件及部门范围，决定旧重复列表接口如何收敛。
- [ ] 区分匿名登录入口、仅需有效登录的本人查询和需要具体管理权限的人员查询；不扩展注册、找回密码等认证功能。
- [ ] 留存原型版本与逐项契约评审结论。仅完成设计评审，不代表正式前端已开发或界面已验收。

## 共享模块及冲突

人员导航、本人信息、分页与错误契约。与 T08/T10 的角色选择和授权入口需要交叉核对，但这些评审可以并行，不因此增加硬依赖。

- 验收项是未来完成条件，全部保持未勾选；拆票获批不等于设计评审或运行验收通过。
- 按交付类型保留原型/契约评审、数据库/HTTP/并发等相应证据；记录实际未验证项。正式前端仍暂缓。
- 提交本票变更供小组评审；前置票的结论与所需产物进入共同基线后，下游才可开始。不得自行合并或顺带认领下游。
