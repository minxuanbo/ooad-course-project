# T14：确认课程系统受控场景及原型/API 契约

**类型：**后续任务：设计评审\
**范围：**课程系统后续，须小组另行确认启动\
**Status:** awaiting-manual-claim\
**平台发布：**待发布；暂无 GitHub Issue 编号。\
**负责人：**待组员认领；本文件不会触发自动领取或实现。

## What to build

选定一个范围明确的真实课程受控操作，确认它如何归属课程系统、由何种角色权限控制，以及可评审的原型和接口契约。

## Blocked by

- [T01](./01-t01-model-review.md)

**阻塞原因：**模型规则是直接前置；不必等待无关的人员功能收尾，但课程场景本身尚待落实。

**额外启动条件：**后续范围启动、课程侧资料与对接边界由小组确认；当前排期仍暂缓，不能因技术阻塞少就自动启动。

## Acceptance criteria

- [ ] 由组员确认课程侧真实业务操作、现有实现/对接方式与资料来源；没有资料时保持待办，不编造接口或扩成完整课程管理系统。
- [ ] 先有课程场景原型，再审核 API 方法、路径、字段、错误、权限及可观察结果；明确与权限系统共用身份的边界，不新增 SSO 或认证功能。
- [ ] 确认课程权限与 API 的系统归属、与权限系统的隔离及双系统授权演示步骤。
- [ ] 记录评审版本与结论，明确 T15 的正式接口实现尚未开始；原型评审不等于课程界面或正式前端验收。

## 共享模块及冲突

应用系统归属、资源登记、身份边界及课程侧接口资料。与 T06/T08 的资源/角色术语需一致；不把“后续排期”写成虚假的 T13 技术依赖。

## 开始与完成

- 开始前阅读[整改执行入口](../../../docs/rbac-rectification/RBAC整改执行入口.md)，逐项核对本票阻塞项和评审证据。
- 只执行用户指定的本票；在独立分支或工作树修改，保护已有未跟踪文档。
- 验收项是未来完成条件，全部保持未勾选；拆票获批不等于设计评审或运行验收通过。
- 按交付类型保留原型/契约评审、数据库/HTTP/并发等相应证据；记录实际未验证项。正式前端仍暂缓。
- 提交本票变更供小组评审；前置票的结论与所需产物进入共同基线后，下游才可开始。不得自行合并或顺带认领下游。
