# T03：把原始组织与人员导入层级部门并核对

**类型：**数据闭环\
**范围：**当前 RBAC 后端整改\
**Status:** awaiting-manual-claim\
**平台发布：**已发布：[Issue #4](https://github.com/minxuanbo/ooad-course-project/issues/4)。\
**负责人：**待组员认领；本文件不会触发自动领取或实现。

## What to build

在整改库中恢复公司、分公司、部门的层级，并让原始人员逐一对应正确部门，组员能独立复核数量、归属与异常。

## Blocked by

- [T02 / #3](https://github.com/minxuanbo/ooad-course-project/issues/3)（[本地镜像](./02-t02-jpa-core.md)）

**阻塞原因：**导入必须写入已经验证的新部门与人员模型。

## Acceptance criteria

- [ ] 公司并入层级部门；根无上级、每个部门最多一个上级，不接受循环、缺失父节点或不明确的人员归属。
- [ ] 按原始数据的实际数量核对约一万人及员工资料，保留已有工号等来源标识；不能凭空假定全部有效或丢弃无法对应的人员。
- [ ] 以明确规则转换账号有效状态并保留必要基础登录字段；不导入统一登录标识、数据库会话或新的凭证模型。
- [ ] 可追溯原组织/人员到新记录的对应；异常单独列出，禁止默默扩权或把旧业务目录一并导入。
- [ ] 重复执行不会重复建人、重复授予默认权限或覆盖已调整授权；失败可回滚或安全重试，原 Excel 与原库保持不变。
- [ ] 提供 MySQL/JPA 导入核对结果及小样本归属验证；尚未完成界面或人员接口验收。

## 共享模块及冲突

组织/人员实体、Excel 读取、数据初始化、状态映射和测试夹具。与 T02/T05/T11 的同类数据入口冲突；只迁移组织和人员，不接管角色资源导入。

## 开始与完成

- 开始前阅读[整改执行入口](../../../docs/rbac-rectification/RBAC整改执行入口.md)，逐项核对本票阻塞项和评审证据。
- 只执行用户指定的本票；在独立分支或工作树修改，保护已有未跟踪文档。
- 验收项是未来完成条件，全部保持未勾选；拆票获批不等于设计评审或运行验收通过。
- 按交付类型保留原型/契约评审、数据库/HTTP/并发等相应证据；记录实际未验证项。正式前端仍暂缓。
- 提交本票变更供小组评审；前置票的结论与所需产物进入共同基线后，下游才可开始。不得自行合并或顺带认领下游。
