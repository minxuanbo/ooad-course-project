# T10：评审人员角色分配与受限人员变更契约

**类型：**原型与契约前置\
**范围：**当前 RBAC 后端整改\
**Status:** awaiting-manual-claim\
**平台发布：**已发布：[Issue #11](https://github.com/minxuanbo/ooad-course-project/issues/11)。\
**负责人：**待组员认领；本文件不会触发自动领取或实现。

## What to build

在原型中走通选择范围内人员、查看当前角色与可分配角色、保存或清空，以及必要人员停用/归属变更的受限反馈。

## Blocked by

- [T01 / #2](https://github.com/minxuanbo/ooad-course-project/issues/2)（[本地镜像](./01-t01-model-review.md)）

**阻塞原因：**需要人员归属、可授予角色及管理范围规则；原型可与人员检索和角色配置评审并行。

## Acceptance criteria

- [ ] 覆盖本部门、下级、同级其他部门，以及无管理权限账号；界面提示不得替代后端权限约束。
- [ ] 审核可分配角色的范围、不能授予超出自身有效权限的角色、部门管理员不能改自己的授权/所属部门或全局管理员。
- [ ] 确认人员停用场景及接口；调部门仅在评审确认需要时纳入，并明确原部门和目标部门都在管理范围内。不默认新建人员/组织全套 CRUD。
- [ ] 明确角色整体替换、空选清空、失败回滚、最后有效管理员保护和错误反馈，形成逐项契约。
- [ ] 与 T04 的人员定位、T08 的角色含义交叉核对并记录结论；此项仅是原型/契约评审，正式前端仍暂缓。

## 共享模块及冲突

人员选择、部门范围、可分配角色、人员状态与授权 DTO。与 T04/T08 可并行评审，冲突在契约结论中解决，不以“同一页面”制造无关阻塞。

## 开始与完成

- 开始前阅读[整改执行入口](../../../docs/rbac-rectification/RBAC整改执行入口.md)，逐项核对本票阻塞项和评审证据。
- 只执行用户指定的本票；在独立分支或工作树修改，保护已有未跟踪文档。
- 验收项是未来完成条件，全部保持未勾选；拆票获批不等于设计评审或运行验收通过。
- 按交付类型保留原型/契约评审、数据库/HTTP/并发等相应证据；记录实际未验证项。正式前端仍暂缓。
- 提交本票变更供小组评审；前置票的结论与所需产物进入共同基线后，下游才可开始。不得自行合并或顺带认领下游。
