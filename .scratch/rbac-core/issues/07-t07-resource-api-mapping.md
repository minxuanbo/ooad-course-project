# T07：让本权限系统资源目录与 API 映射真实生效

**类型：**后端业务闭环\
**范围：**当前 RBAC 后端整改\
**Status:** awaiting-manual-claim\
**平台发布：**待发布；暂无 GitHub Issue 编号。\
**负责人：**待组员认领；本文件不会触发自动领取或实现。

## What to build

有对应管理权限的根部门账号能按已批准场景核对和维护资源映射，保存结果能被真实接口鉴权使用；非法关联和无权修改被拒绝。

## Blocked by

- [T05](./05-t05-identity-query-authorization.md)
- [T06](./06-t06-resource-api-review.md)

**阻塞原因：**复用首个真实鉴权链路，并严格依赖资源配置对应契约评审。

## Acceptance criteria

- [ ] 仅实现 T06 确认的资源操作，通过 JPA 持久化，并可由真实 HTTP 读取保存结果；不自动补齐全套 CRUD。
- [ ] 权限及 API 各属单一系统，映射同系统；权限树禁止循环、按钮不能有子节点，唯一性与失败回滚有验证。
- [ ] 管理请求同时满足根部门和实际对应权限；普通根部门成员、无权限用户均不能修改。
- [ ] 同一 API 关联多个权限时任一有效授权可放行；停用或解除关联后的后续请求使用最新有效授权，不能依赖令牌过期。
- [ ] 对会使最后有效全局管理员失去必要维护能力的变更，事务内拒绝并验证并发路径；不能只防用户停用而漏掉本票的资源/映射变更。
- [ ] 资源来自已评审且实际存在的权限系统接口；清理本切片旧目录/模拟功能鉴权调用、初始化、测试、配置和说明，给出真实允许/拒绝证据。

## 共享模块及冲突

权限树、API 登记/映射、AOP 查询、初始化、事务与管理员保护。与 T09/T11 共享有效授权计算和保护检查，避免各自采用不同锁或判定。

## 开始与完成

- 开始前阅读[整改执行入口](../../../docs/rbac-rectification/RBAC整改执行入口.md)，逐项核对本票阻塞项和评审证据。
- 只执行用户指定的本票；在独立分支或工作树修改，保护已有未跟踪文档。
- 验收项是未来完成条件，全部保持未勾选；拆票获批不等于设计评审或运行验收通过。
- 按交付类型保留原型/契约评审、数据库/HTTP/并发等相应证据；记录实际未验证项。正式前端仍暂缓。
- 提交本票变更供小组评审；前置票的结论与所需产物进入共同基线后，下游才可开始。不得自行合并或顺带认领下游。
