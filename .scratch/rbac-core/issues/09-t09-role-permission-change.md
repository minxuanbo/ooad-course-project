# T09：让角色权限配置改变真实 API 访问结果

**类型：**后端业务闭环\
**范围：**当前 RBAC 后端整改\
**Status:** awaiting-manual-claim\
**平台发布：**已发布：[Issue #10](https://github.com/minxuanbo/ooad-course-project/issues/10)。\
**负责人：**待组员认领；本文件不会触发自动领取或实现。

## What to build

具备权限的全局维护者给角色配置或撤销权限后，该角色用户在后续真实请求中立即得到相应允许/拒绝结果。

**阻塞原因：**需要通用的真实接口鉴权和相应契约；可使用已确认的初始化权限，不必等待 T07 的资源维护接口。

## Acceptance criteria

- [ ] 按 T08 契约用 JPA 处理必要角色定义、角色状态和角色权限配置；同一权限可用于多个角色，不另保留独立管理权限模型。
- [ ] 整体替换成功或回滚，空选为撤销；非法、不可用或跨越约定边界的数据被拒绝，原授权不变。
- [ ] 新增、撤销权限或停用角色后，已有登录身份的后续请求按最新授权判断；无角色及只授父菜单的结果正确。
- [ ] 修改要求实际对应权限与根部门条件，最后有效管理员保护覆盖角色权限/状态变更，事务和并发拒绝路径均有验证。
- [ ] 只迁移能明确对应的新角色及权限；旧角色名绑定范围规则不沿用，无法对应的旧授权不启用并列出差异。
- [ ] 迁移本切片的 JDBC、调用、初始化、测试、配置和说明；用已有受控 HTTP 场景证明授权变化，正式前端不在交付范围。

## 共享模块及冲突

角色、角色权限、有效授权查询、管理权限判定、事务与管理员保护。与 T07/T11 存在共享模块冲突；没有硬依赖不等于可以同时覆盖同一公共实现。

- 开始前阅读[整改执行入口](../../../docs/rbac-rectification/RBAC整改执行入口.md)，逐项核对本票阻塞项和评审证据。
- 只执行用户指定的本票；在独立分支或工作树修改，保护已有未跟踪文档。
- 验收项是未来完成条件，全部保持未勾选；拆票获批不等于设计评审或运行验收通过。
- 按交付类型保留原型/契约评审、数据库/HTTP/并发等相应证据；记录实际未验证项。正式前端仍暂缓。
- 提交本票变更供小组评审；前置票的结论与所需产物进入共同基线后，下游才可开始。不得自行合并或顺带认领下游。
