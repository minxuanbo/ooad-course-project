# T01：确认核心模型、授权规则与逐块替换边界

**类型：**评审前置\
**范围：**当前 RBAC 后端整改\
**Status:** awaiting-manual-claim\
**平台发布：**待发布；暂无 GitHub Issue 编号。\
**负责人：**待组员认领；本文件不会触发自动领取或实现。

## What to build

小组获得一份已确认的核心模型、需求归属和迁移对照，能据此分别认领实现；本票以评审记录验收，不写正式接口。

## Blocked by

无；可由用户指定后开始。

**阻塞原因：**先明确需要保留和替换的规则，避免把旧模型继续带入新实现。

## Acceptance criteria

- [ ] 逐项对照检查记录及原版 v0.6，核对六个核心实体、三组多对多、部门与权限树；九张表、全局共享角色、单部门归属等明确标为方案建议。
- [ ] 确认有效账号可登录、无管理权限提示、管理请求同时校验具体权限和部门范围；不增加管理员属性、独立登录资格或认证新功能。
- [ ] 明确有效全局管理员的权限判定、根部门的范围作用，以及哪些变更会影响其有效性；禁止以角色名替代判定。
- [ ] 形成“复用、替换、删除”的业务对照：保留工程骨架、响应与异常处理、可用的数据读取和测试方法；替换错误组织/授权模型及直接 JDBC 业务实现。
- [ ] 列明旧会话与统一标识依赖的最小衔接方案、保留的基础登录字段，以及旧功能的调用方、初始化、测试、配置、文档清理范围；不在本票设计令牌格式或生命周期。
- [ ] 记录评审人、结论和未决项；涉及原版建议变更时先回写原版，相关下游票保持阻塞。

## 共享模块及冲突

模型与术语、初始化边界、当前身份、授权规则。与所有下游票共享；后续改变这些约定须先同步评审。

## 开始与完成

- 开始前阅读[整改执行入口](../../../docs/rbac-rectification/RBAC整改执行入口.md)，逐项核对本票阻塞项和评审证据。
- 只执行用户指定的本票；在独立分支或工作树修改，保护已有未跟踪文档。
- 验收项是未来完成条件，全部保持未勾选；拆票获批不等于设计评审或运行验收通过。
- 按交付类型保留原型/契约评审、数据库/HTTP/并发等相应证据；记录实际未验证项。正式前端仍暂缓。
- 提交本票变更供小组评审；前置票的结论与所需产物进入共同基线后，下游才可开始。不得自行合并或顺带认领下游。

**依据：**原版执行计划 v0.6；检查记录及用户确认补充决定需求范围。讨论版、旧文档和旧实现不取代原版。
