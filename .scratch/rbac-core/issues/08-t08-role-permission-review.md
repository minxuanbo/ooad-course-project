**Status:** awaiting-manual-claim\
**平台发布：**待发布；暂无 GitHub Issue 编号。\

## What to build

组员能在原型中理解角色所含权限、父菜单与子按钮的区别，确认必要角色维护和权限保存/撤销行为及对应接口。

## Blocked by

**阻塞原因：**角色与权限模型是前置；不必等待资源维护页面或其接口完成。

## Acceptance criteria

- [ ] 覆盖角色查询、权限树已选状态、保存成功/失败、空选清空以及本轮需要的启用/停用；仅确认必要的角色定义维护，不扩展角色继承、版本或审批。
- [ ] 父菜单不自动授予子按钮；导航补祖先只影响展示，不改变所选权限。
- [ ] 明确全局共享角色、根部门且有对应权限才可修改等方案默认，并记录是否接受；不把这些写成老师逐项规定。
- [ ] 审核整体替换、错误回滚、停用后生效、最后有效管理员保护的契约；以实际权限判断管理员，不按角色名。
- [ ] 形成原型与逐项接口契约评审结论；没有正式前端开发或界面验收结论。

## 共享模块及冲突

角色/权限 DTO、权限树原型、停用与授权语义。与 T06 共享资源展示，与 T10 共享可分配角色的含义。

## 开始与完成

- 开始前阅读[整改执行入口](../../../docs/rbac-rectification/RBAC整改执行入口.md)，逐项核对本票阻塞项和评审证据。
- 只执行用户指定的本票；在独立分支或工作树修改，保护已有未跟踪文档。
- 验收项是未来完成条件，全部保持未勾选；拆票获批不等于设计评审或运行验收通过。
- 按交付类型保留原型/契约评审、数据库/HTTP/并发等相应证据；记录实际未验证项。正式前端仍暂缓。
- 提交本票变更供小组评审；前置票的结论与所需产物进入共同基线后，下游才可开始。不得自行合并或顺带认领下游。
