# 市政公司统一权限管理系统——需求分析

版本：6.0；日期：2026-10-27。

## 1. 文档目的与范围

本文规定业务目标、参与者、系统边界、功能需求、业务规则、非功能要求及验收准则，作为界面、API、数据库和详细设计的共同输入。需求以可观察行为和业务约束表达，不记录开发进度或执行结果。

系统面向多公司、多部门人员的统一身份认证、RBAC0 功能授权和组织范围管理。三份业务资料——员工信息表、部门信息表、应用软件功能权限清单——作为空库初始化输入。人员、部门、系统和权限数量由输入资料决定，不固化为业务限制；容量设计按万级人员规模考虑。

技术约束为 Spring Boot 后端、Vue 前端和 MySQL 关系数据库。系统提供权限管理、目录展示和鉴权交互，不代替外部应用执行业务。

## 2. 业务目标与成功判据

| 目标 | 业务问题 | 成功判据 |
| --- | --- | --- |
| 统一身份 | 同一人员在多系统中难以统一识别 | 用户名、工号、手机号唯一定位同一身份，停用或失效会话被拒绝 |
| 明确授权 | 菜单可见不等于有权调用接口 | 后端独立校验每次业务鉴权及管理请求 |
| 控制管理范围 | 公司或部门管理员可能越权处理其他组织人员 | 管理操作与同角色范围同时命中，查询和写入均不得扩大范围 |
| 集中离职处置 | 分散撤权容易遗漏账号或会话 | 完成离职时角色、范围、账号、会话和记录原子变更 |
| 支持追溯 | 认证拒绝、权限变更缺乏统一记录 | 规定的认证、鉴权和管理事件留痕，可按授权查询和归档 |
| 降低使用歧义 | 角色定义、员工分配、管理范围容易混淆 | 界面分别表达三种操作，说明影响对象和保存范围 |

## 3. 术语与参与者

### 3.1 术语

- **业务权限**：外部应用功能点与动作的组合，例如某功能的查看或审批许可。
- **管理操作**：本权限平台的人员查询、角色分配、组织维护、日志读取等操作能力。
- **管理范围**：员工所持某一角色可管理的全平台、公司或精确部门集合。
- **系统准入**：用户至少拥有一个目标应用的有效权限，可以进入其功能目录；不代表拥有所有操作。
- **鉴权结果**：对权限的允许／拒绝判断；不表示外部业务操作已经执行或成功。
- **平台／公司／部门管理员**：按有效管理授权描述的使用身份，不是额外创建的角色名称。

### 3.2 参与者及职责

| 参与者 | 职责 | 边界 |
| --- | --- | --- |
| 普通员工 | 登录、查看自身应用和权限、请求系统准入与功能鉴权 | 没有有效管理授权时不能读取管理数据 |
| 平台管理员 | 在具体 GLOBAL 管理操作权限下维护全平台资源 | 角色名称本身不替代操作权限与范围校验 |
| 公司范围管理员 | 按所授管理操作处理指定公司人员与组织 | 不得处理范围外公司，不得修改共享角色权限定义 |
| 部门范围管理员 | 按所授操作处理一个或多个精确部门 | 不递归包含子部门；不凭部门范围新增部门 |
| 交接接收人 | 承接业务资料和工作 | 不自动获得离职人员角色或权限 |
| 交接负责人 | 作为交接记录的责任人员 | 关联到记录不代表取得完成处置的操作权限 |
| 业务调用方 | 携带用户令牌调用鉴权，独立执行自身业务事务 | 不将平台允许结果当作业务执行成功证明 |
| 组织资料提供方 | 提供员工、部门与功能权限清单 | 数据输入为初始化资料，不定义持续 HR 同步协议 |

角色目录定义系统管理员、公司领导、部门经理、项目经理、普通员工五类。部长／副部长映射为部门经理；项目经理／项目副经理／项目总工程师映射为项目经理。岗位是初始角色分配依据，显式授权可以独立调整员工管理范围。

### 3.3 系统边界

范围内包括统一认证、应用目录与鉴权、人员查询、业务角色和管理操作配置、员工角色范围、公司部门新增与编码名称维护、离职处置和审计查询归档。

范围外包括角色继承与互斥角色、通用用户／角色／系统目录 CRUD、组织移动或部门层级、密码重置、复职和交接撤销、HR 增量同步、OA 审批引擎与可信回调、SSO、真实业务 CRUD、外部业务系统内部数据范围、通用报表和自动日志销毁。OA 单号仅作为参考字段。

“我的应用”用于展示已获授权的系统并进入功能鉴权交互，不定义集团综合门户或真实系统跳转集成。

## 4. 业务规则

### 4.1 RBAC0 与身份

1. 用户可以持有多个角色，角色可以包含多个应用的业务权限；有效权限取启用角色权限的去重并集，未命中即拒绝。
2. 所有启用的已分配角色参与鉴权，不提供逐会话激活角色的选择。
3. 用户、会话、角色、权限、应用、模块、功能点和动作的有效性共同决定访问许可。
4. 撤销某角色不应撤销其他角色独立授予的相同权限。
5. 用户名、工号、非空手机号共享唯一登录空间；同用户多个字段同值允许，不同用户跨字段占用同值必须拒绝，包含并发写入。
6. 空库导入与默认授权作为整体初始化；非空库不重复导入或恢复人工撤销的权限。

### 4.2 管理权限与组织范围

| 范围 | 组织字段 | 目标集合 |
| --- | --- | --- |
| GLOBAL | 公司、部门均为空，仅系统管理员角色使用 | 全平台，包含无部门账号 |
| COMPANY | 指定公司，不指定部门 | 该公司所属部门及其人员 |
| DEPARTMENT | 输入公司和部门用于归属校验；持久化只存部门 | 精确选定部门／项目部及其人员 |

管理操作必须与员工**同一角色**的范围共同匹配。角色 A 的人员查询权与角色 B 的另一公司范围不能组合为角色 A 的跨公司权限。同一角色可分配多个范围；无范围的角色仍可产生业务功能权限，但不产生管理权。

人员列表、总数、筛选项与相关统计必须使用对应管理操作的同一范围条件。外部查询参数只能缩小结果，不能扩大授权。

共享角色业务权限和管理操作定义只允许 GLOBAL role.permissions 配置；员工管理范围只允许 GLOBAL management.grant 配置；全局鉴权日志只允许系统管理员角色下 GLOBAL audit.read 读取。不存在独立审计员角色。

局部管理员不得修改自己或有效管理授权持有者的业务角色，也不得为受保护管理账号办理离职。局部角色分配时，目标原角色及新角色的业务权限必须属于操作者有效权限子集。

必须保留至少一名启用、持有启用系统管理员角色且具有 GLOBAL management.grant 的人员。触犯此条件的角色配置、范围变更或离职事务整体拒绝。

### 4.3 授权保存与组织维护

- 角色、权限、员工角色范围使用集合替换语义。保留角色时保留其原范围，撤销角色级联撤销其范围；普通角色分配不为新增角色自动赋予管理范围。
- 角色的操作定义影响全部该角色持有者；员工角色范围只改变目标员工的管理边界。
- 公司和部门只有两级关系，不定义上级部门或上级公司字段。公司维护仅平台范围；部门新增需所属公司的 COMPANY 或 GLOBAL org.write；精确部门范围只维护已有部门。
- 组织编码和名称使用 PATCH 局部更新，省略字段保留原值；不允许借此修改归属、负责人、启用状态或删除实体。
- 授权变化以事务提交为生效边界。后续请求重新判断权限；不承诺中断已通过鉴权的外部在途事务。

### 4.4 离职与审计

账号 ACTIVE／DISABLED 与交接状态独立。无交接记录派生为 EMPLOYED，交接记录状态为 HANDOVER 或 DEPARTED。
发起对象必须启用、无既有交接且不是当前操作者。接收人与负责人均为启用、无交接记录且不是离职本人的员工，并属于 handover.start 操作范围；两人可以为同一人。
发起保留原授权；预计日期不触发自动完成，也不要求晚于当前日期。完成时必须明确确认，在同一事务内撤角色和范围、停用账号、撤销会话、记录完成状态和审计；重复完成在权限校验后成功返回。

认证事件包括登录成功／失败、API 未认证与权限拒绝；业务事件包括功能鉴权和应用准入；管理变更单独留痕。无法识别主体时允许用户 ID 为空；日志禁止包含密码、令牌、完整请求体或查询串。不存在的应用是资源错误，不伪装为有效应用上的权限判断。
日志归档保留事件与查询能力，不删除原事件，也不承诺减少数据库物理占用。

## 5. 功能需求与验收条件

| 编号 | 功能需求 | 可观察的验收条件 |
| --- | --- | --- |
| REQ-01 | 空库初始化 | 三份输入建立组织、人员、角色、目录和默认授权；失败无部分业务导入，非空库重启保留人工授权 |
| REQ-02 | 登录与退出 | 三种登录标识均可认证；无效凭据统一拒绝；退出后当前令牌不可继续使用 |
| REQ-03 | 我的应用与功能目录 | 只展示当前有效应用；单应用场景执行准入校验；各操作按实时 allowed 呈现 |
| REQ-04 | 管理入口隔离 | 菜单、路由按具体管理操作控制，直接调用接口仍受后端鉴权 |
| REQ-05 | 范围内人员查询 | 公司、部门、关键词组合筛选；包含电话、状态与分页总数；越界筛选不泄漏人员 |
| REQ-06 | 用户业务角色分配 | 保存完整选择集合，清空可撤销；保留角色范围不丢失，受保护目标和越权分配被拒绝 |
| REQ-07 | 角色权限定义 | 分别配置业务功能和管理操作；筛选不丢失隐藏选项选择；共享影响范围明确 |
| REQ-08 | 功能鉴权 | 应用码和权限码共同匹配；业务拒绝返回 allowed=false，不能混同接口调用异常 |
| REQ-09 | 动态撤权 | 相同会话在授权变更后的新请求读取新权限，不要求用户重新登录 |
| REQ-10 | 离职交接与完成 | 发起保留权限，完成原子撤权；无取消、回退、复职或权限自动转交 |
| REQ-11 | 审计留痕 | 规定的认证／鉴权和管理变更可追溯；未知主体可记录，敏感凭据不落日志 |
| REQ-12 | 工作台与目录查询 | 人员相关统计按范围；缺目录或日志查看权时相应统计为 0 |
| REQ-13 | 技术与数据契约 | 前后端分离、MySQL 持久化、UTF-8 中文、UTC 日期时间及明确 DTO |
| REQ-14 | 细粒度管理授权 | 操作与同角色范围匹配，多范围兼管，平台专属操作及最后管理员保护成立 |
| REQ-15 | 公司部门维护 | 查看与维护权分离；新增约束和 PATCH 字段规则有效，组织归属不被隐式改写 |
| REQ-16 | 外部系统边界 | 鉴权结果、OA 单号与接收人记录不被解释为真实业务执行、自动审批或权限转移 |
| REQ-17 | 日志检索 | 支持用户、系统、结果、事件、UTC 时间及归档状态；游标后页保持首屏条件 |
| REQ-18 | 日志归档 | 仅 GLOBAL audit.read 可按截止时间分批归档；说明作用于全部日志且保留查询 |
| REQ-19 | 稳定接口响应 | 成功／错误均使用 code、message、data、requestId；HTTP 状态及业务错误语义可区分 |
| REQ-20 | 登录标识与数据完整性 | 数据库拒绝跨用户标识冲突；外键、范围 CHECK 与规范化组织关系有效 |

### 5.1 人员查询规则

关键词在姓名、用户名、工号、手机号中按 OR 匹配，关键词与公司、部门之间按 AND 组合。公司按名称精确匹配，部门按 ID 精确匹配；关键词按 LIKE 模式处理，% 和 _ 保留模式字符语义。
切换公司清空部门并回到第 0 页；筛选项只提供授权范围内有人员关联的组织。前端每页 20 人，缺手机号显示“—”，手机号不转换为数值。

### 5.2 日志查询规则

结果按日志 ID 倒序；首次最大 ID 作为上界，后页使用游标，不提供页码跳转。上界排除后续更大 ID 的事件，但不构成跨页数据库事务快照；归档状态和事务提交顺序可能影响可见集合。
时间区间含开始、不含结束；界面本地时间转 UTC 提交。归档目标不受列表上的用户或系统筛选限制，每批处理独立事务；需要新事件时重新查询首屏。

## 6. 主要用例

| 用例 | 前置条件 | 主成功场景 | 失败及后置条件 |
| --- | --- | --- | --- |
| UC-01 认证 | 已导入有效身份 | 输入账号密码→校验→建立会话→读取个人授权 | 无效或停用账号拒绝；不泄漏账号存在与否 |
| UC-02 人员检索 | user.read 生效 | 组合筛选→范围过滤→返回当前页和总数 | 无结果明确展示；任何筛选不得扩大授权 |
| UC-03 业务角色分配 | user.roles 且目标可管理 | 读取角色选项→修改集合→校验保护与子集→事务保存 | 失败整体不变；新增角色不自动获得管理范围 |
| UC-04 管理授权 | GLOBAL management.grant | 选择角色→添加该角色范围→保存整体分配 | 非法范围或最后管理员保护失败时整体回滚 |
| UC-05 共享角色配置 | GLOBAL role.permissions | 读取业务／管理操作选项→保存对应完整集合 | 影响该角色全部持有者，员工范围不被改写 |
| UC-06 动态应用访问 | 已登录 | 加载应用→准入校验→模块／功能→请求鉴权 | 撤权后新请求拒绝，外部业务由调用方独立执行 |
| UC-07 组织维护 | 对应 org.write | 新增公司／部门或修改编码名称→校验→保存 | 重复编码或越权拒绝；省略字段保留 |
| UC-08 离职处置 | 对应离职操作及目标范围 | 发起交接→业务交接确认→完成撤权 | 自办离职、非法关联人、重复发起拒绝；完成全成或全败 |
| UC-09 审计查询 | GLOBAL audit.read | 设置筛选→查询首屏→沿游标继续 | 条件不一致的游标拒绝，普通员工和局部管理员拒绝 |
| UC-10 批量归档 | GLOBAL audit.read | 指定截止时间→确认全局影响→归档本批→按需要继续 | 不删除事件，不按列表筛选局部归档，失败不部分提交本批 |

## 7. 非功能要求与设计约束

| 编号 | 类别 | 规范要求与边界 |
| --- | --- | --- |
| NFR-01 | 安全 | 密码使用 BCrypt，令牌只存 SHA-256；后端独立核验授权；数据库参数绑定；响应不泄漏 SQL 或堆栈 |
| NFR-02 | 隐私 | 人员资料按管理范围返回，交接关联人越界时遮蔽；无字段级加密或普遍脱敏承诺 |
| NFR-03 | 一致性 | 授权、组织更新、离职与管理审计在事务内；管理写操作串行校验，避免撤权与后续写入交错越权 |
| NFR-04 | 时效性 | 授权提交后的新请求重新读取；前端身份刷新只改善反馈，不承担安全保证 |
| NFR-05 | 故障处理 | 认证／授权失败或网络异常不得默认为允许；非幂等写入不得无条件自动重试 |
| NFR-06 | 容量 | 按万级人员设计分页和索引；人员页上限 100、日志页上限 500、范围上限 200、归档批次上限 5000；不设无依据的 QPS 或时延承诺 |
| NFR-07 | 留存 | 不提供自动事件删除；逻辑归档可查。长期存储容量、恢复目标和外部冷存储另行约定，不将逻辑归档等同于灾备 |
| NFR-08 | 可维护性 | Controller／Service／Repository／DTO 职责分离，数据库配置外置；需求、接口、模型与设计保持一致 |
| NFR-09 | 易用性 | 同一导航外壳，明确区分加载、无结果、错误与成功；危险操作说明影响对象，键盘可操作基本表单 |
| NFR-10 | 适配 | UTF-8 中文，现代浏览器，窄屏表格在容器内横向滚动；不将适配目标解释为特定浏览器认证结论 |

## 8. 验收场景与追踪

本节定义验收方法与预期结果，不记录执行成绩。接口验证、独立数据库验证和界面验证共同覆盖需求。

| 场景 | 关联需求 | 预期结果 | 详设标识 |
