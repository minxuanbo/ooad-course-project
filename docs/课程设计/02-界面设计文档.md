# 市政公司统一权限管理系统——界面设计文档

版本：1.0；日期：2026-10-08；对应阶段：RBAC0；实现：Vue 3 单文件组件 + Vue Router + 原生 CSS。

## 配套交互原型

[打开 06-界面原型.html](06-界面原型.html)（新增于 2026-10-13）。下载或在本机直接用浏览器打开，无需启动前后端、无需联网。原型使用内嵌 HTML/CSS/JavaScript，展示现有 Vue 页面的主要交互，不替代实际应用。

可演示管理员/普通员工切换、工作台、公司部门联动筛选、电话查询、分页、用户角色与角色权限勾选、系统准入提示、模拟撤权、离职交接以及本次演示鉴权日志。数据均为虚构；只保存在当前页面内存，刷新或点击“重置演示”恢复，不访问实际数据库。

为便于讲解，原型缩减为 6 名员工、4 个系统、8 项权限，每页 3 人；登录使用身份选择代替真实密码认证，交接使用示例人员选择代替工号验证，“模拟后台撤权”仅为演示控件。真实界面与安全规则仍以下文及后端实现为准。

## 1. 设计目标与系统边界

界面服务于统一登录、个人系统选择和授权管理。前端独立运行于开发端口 5173，调用 Spring Boot API，由后端访问 MySQL。前端无数据库直连、无管理权限最终判定权。

设计原则：普通员工只看本人授权；管理员按组织快速定位员工；授权状态与业务系统接入状态分开；危险操作明确确认；加载、空数据、错误和登录失效均给出反馈。本文描述已实现界面，不将未来 CRUD 原型写成现有页面。

## 2. 信息架构与页面权限

| 编号 | 页面/组件 | 路由或入口 | 可访问者 | 主要接口 |
|---|---|---|---|---|
| UI-01 | 统一登录 Login.vue | /login | 所有人 | POST /api/auth/login、GET /api/me |
| UI-02 | 我的应用 Portal.vue | /portal | 已登录用户 | GET /api/me/applications、POST /api/me/applications/{id}/enter |
| UI-03 | 工作台 Management.vue | /dashboard | 系统管理员 | GET /api/dashboard |
| UI-04 | 用户与授权 Users.vue | /users | 系统管理员 | GET /api/users/page、/api/users/filters |
| UI-05 | 用户角色弹窗 RoleEditor.vue | 用户行“分配角色” | 系统管理员 | GET/PUT /api/users/{id}/roles |
| UI-06 | 角色与权限 Management.vue | /roles | 系统管理员 | GET /api/roles |
| UI-07 | 角色权限弹窗 RoleEditor.vue | 角色卡片“配置角色权限” | 系统管理员 | GET/PUT /api/roles/{id}/permissions |
| UI-08 | 业务系统 Management.vue | /apps | 系统管理员 | GET /api/applications |
| UI-09 | 鉴权日志 Management.vue | /logs | 系统管理员 | GET /api/authorization-logs |
| UI-10 | 离职交接 Handover.vue | 用户行“离职交接” | 系统管理员 | 交接查询、发起及完成接口 |

路由 / 重定向至 /portal；未知路由也转向 /portal。除登录页外先查询 /api/me；无令牌进入登录页，无管理权限访问管理路由退回我的应用。所有管理数据在后端再次检查，不能依赖上述路由守卫。

## 3. 全局布局与视觉规范

桌面采用左侧导航、顶部身份栏、右侧内容区。侧栏展示系统标识、导航和服务说明；顶部展示当前姓名、头像首字和退出入口。内容区包含标题、说明、刷新按钮、主体和页脚。

```text
┌──────────────┬────────────────────────────────────────┐
│ 统一权限管理 │ 集团 / 权限管理平台          姓名  退出 │
│              ├────────────────────────────────────────┤
│ 我的应用     │ 页面标题                     刷新数据  │
│ 工作台       │ 页面说明                               │
│ 用户与授权   │ ┌────────────────────────────────────┐ │
│ 角色与权限   │ │ 卡片 / 筛选工具栏 / 数据表格       │ │
│ 业务系统     │ └────────────────────────────────────┘ │
│ 鉴权日志     │ 页脚                                   │
└──────────────┴────────────────────────────────────────┘
```

普通员工仅展示“我的应用”；这是同一前端壳层中的受限导航，不代表授予管理后台访问权。

| 元素 | 规范 |
|---|---|
| 背景 | 浅灰蓝 #f5f7fb，白色卡片、浅色边框 |
| 主色 | 蓝色 #3865e8；主按钮白字 |
| 文本 | 深色标题、灰蓝辅助信息；不只靠颜色区分状态 |
| 状态标签 | 绿色“有权限/已启用”；红色“无权限/拒绝”；灰色其他状态 |
| 间距与圆角 | 卡片常用 10–12px 圆角，内容区与表格保持层次 |
| 字体 | 系统无衬线中文字体；工号与电话使用等宽字体 |
| 工作台入口 | 圆角蓝色链接按钮，至少 44px 高，独立细线箭头、轻阴影、悬停反馈 |
| 焦点与动效 | 可见键盘焦点；入口箭头动效遵循 reduced-motion 偏好 |

主要响应式断点为 1050px 和 720px，筛选栏另在 760px 调整为纵向。窄屏隐藏登录故事区，导航横向排列；表格在容器内部横向滚动，页面主体不横向溢出。桌面与窄屏共享同一功能与后端权限规则。

## 4. 页面详细设计

### 4.1 UI-01 统一登录

桌面左侧为深蓝品牌故事与“用户—角色—权限”关系示意，右侧为登录表单；窄屏只保留登录表单。

| 控件 | 类型与规则 | 交互 |
|---|---|---|
| 账号 | 文本框，必填，autocomplete=username | 提交时 trim；支持工号、手机号、用户名 |
| 密码 | 密码框，必填，autocomplete=current-password | 显示/隐藏按钮只改变显示方式 |
| 登录 | 表单提交按钮 | 提交期间禁用并显示“正在验证身份…” |
| 错误区 | alert 文本 | 密码错误、停用或连接失败显示具体反馈 |
| 演示说明 | 课程账号提示 | 仅演示环境；不代表生产初始密码策略 |

登录成功保存当前标签页 sessionStorage 中的令牌，查询身份后进入我的应用。单个可用系统自动执行实时准入校验；当前没有业务跳转地址，故显示“有权限但暂未接入”。账号密码错误时不区分账号不存在与密码不正确，避免不必要的信息暴露。

### 4.2 UI-02 我的应用

顶部显示有权访问的系统数量、说明和最近同步时间。卡片列出系统名称、有权/无权标签、当前有效权限数量、接入说明与操作按钮。

| 当前状态 | 卡片展示 | 点击反馈 |
|---|---|---|
| 有权限、未接入 | “有权限”“暂未接入”“进入系统” | 后端准入成功，提示有权但未接入 |
| 无权限或系统停用 | “无权限”“未获授权、授权已回收或系统已停用” | “检查访问权限”，后端拒绝并提示原因 |
| 进入后被撤权 | 卡片与结果区随后更新 | 所选系统显示已失去访问权限 |
| 网络不可用 | 最近状态可能已过期的提示 | 不提供离线放行或伪造跳转 |

每 3 秒及窗口重新获得焦点时同步。轮询不是授权缓存，入口请求每次到后端重查。多系统用户自行选择；“暂未接入”不应被误写为“无权限”。

### 4.3 UI-03 工作台

欢迎卡片包含“进入用户授权”入口，跳转 /users。统计卡片显示组织用户、授权角色、系统目录、操作权限数量；下方展示授权流程、部门数量和鉴权日志数量。

数量是数据库记录统计，不是当前在线人数、已接入系统数或有效权限的实时聚合报表。工作台不包含新增用户按钮。

### 4.4 UI-04 用户与授权

```text
所属公司 [全部公司 ▼]  所属部门 [全部部门 ▼]
员工搜索 [姓名、工号或手机号________] [查询] [重置]
员工 | 工号 | 电话 | 所属组织 | 岗位 | 当前角色 | 账号/人员状态 | 操作
...                                                            分配角色 / 离职交接
共 N 人 · 第 P / T 页                                  上一页  下一页
```

公司/部门选择即查询；关键词按查询按钮或回车提交。公司变化先清空部门和页码，再获取匹配部门选项与第一页数据；部门变化也回到第一页。重置恢复全部公司、全部部门、空关键词、第一页。

表格字段：

| 字段 | 显示规则 |
|---|---|
| 员工/工号 | 姓名与 employeeNo，稳定内部 ID 不作为主要展示 |
| 电话 | 原始字符串；缺失显示“—” |
| 所属组织 | 公司主行、部门次行；缺失显示“—” |
| 岗位 | 展示 position，不据此直接授予管理权 |
| 当前角色 | 角色名称以“、”拼接；空时“未分配角色” |
| 账号/人员状态 | 已启用/已停用 + 在职/离职交接中/已离职 |
| 操作 | 分配角色、离职交接；已离职者禁用分配角色 |

每页 20 人，总页数由 total 计算；第一页禁用上一页，末页禁用下一页；空结果显示“未找到匹配的用户”。查询时显示加载行，失败时显示错误且清空当前列表。请求序号阻止较慢的旧查询覆盖新查询结果。

### 4.5 UI-05/07 授权弹窗

采用原生 dialog 模态窗口。标题为用户或角色名称，包含关闭按钮、说明、筛选框、可滚动复选项、已选择数量、错误区、取消与保存按钮。

用户角色选项显示角色名；角色权限选项显示“系统 / 模块 / 功能 / 操作”。首次一次性加载完整选项，筛选仅影响可见集合，不修改 selected ID 数组。保存提交完整 IDs，包括当前被搜索隐藏但仍勾选的项。

保存过程中禁用选择和保存；首次加载失败不能保存空数据。保存成功关闭弹窗、提示“授权已保存”、刷新所在页面；失败保留选择并提示，可重试。取消、关闭或 Escape 不提交变更。清空所有复选框再保存表示明确回收全部关系。

### 4.6 UI-06 角色与权限

角色卡片展示名称、启用状态、描述、关联用户数及权限条目数，提供“配置角色权限”。卡片数量从后端读取。当前没有新增、删除、重命名角色的表单，也没有角色继承树。

### 4.7 UI-08 业务系统

系统卡片展示名称、启用状态、权限条目数、系统代码与“暂未接入”。这是目录查看，不是业务功能页面；尚无系统注册/删除/切换启用状态的前端入口。

### 4.8 UI-09 鉴权日志

表格展示最近 100 条记录：UTC 时间、用户名、目标系统、权限编码、允许/拒绝和原因，按最新优先。空列表给出暂无记录提示。没有日期高级筛选、导出或无限分页；不能将当前页面描述为完整审计报表中心。

### 4.9 UI-10 离职交接

公共区显示人员与账号状态、当前角色、当前有效系统折叠区、最近 50 条变更记录。按状态渲染：

| 状态 | 输入与展示 | 提交 |
|---|---|---|
| 在职 | 接收人工号、负责人工号、预计日期、说明、可选 OA 单号；提示原权限保留 | 开始离职交接 |
| 交接中 | 原交接信息只读；完成说明；集中撤权及停用确认复选框 | 完成离职处置 |
| 已离职 | 完成时间、完成说明、保留历史说明 | 无提交按钮 |

说明最长 1000 字，工号最长 100 字，OA 单号最长 200 字；日期采用 date 控件。完成前红色提示会回收全部角色、停用账号并撤销会话。页面不模拟 OA 审批、不自动给接收人授权。

## 5. 全局状态与异常设计

| 场景 | 处理 |
|---|---|
| 接口 401 | 清除当前令牌，返回登录并提示登录失效 |
| 管理权限被回收 | 轮询识别后卸载管理页面/弹窗，回到我的应用；后端此前已拒绝请求 |
| 管理接口 403 | 显示无权限；不以隐藏按钮替代接口限制 |
| 请求超过 20 秒或断网 | 报连接失败；用户可重试 |
| 正常接口空响应体 | 视为成功，避免 JSON 解析异常 |
| 普通提示 | 底部通知区，通常 6 秒后消失 |
| 系统准入结果 | 页面内持续结果区，不只依赖瞬时通知 |
| 外部输入展示 | Vue 文本插值，不以 v-html 注入人员或日志内容 |

## 6. 交互验收清单

1. 管理员能看到全部导航，普通员工只能看到我的应用；直接输入 /users 仍被拦截。
2. 公司变化后不残留其他公司的部门选择；按电话可准确定位，空电话不显示 null。
3. 搜索权限后已选总数不变；取消不修改后端数据。
4. 开始交接保留权限，完成时必须确认，已离职状态禁用角色分配。
5. 401 后弹窗不会继续保留为可操作的管理窗口。
6. 窄屏下表格横向滚动不挤出页面；按钮焦点、标签、加载和错误提示可辨识。
7. 工作台入口点击可进入用户页，文字留白、箭头和悬停状态正常。

接口字段详见[API设计](03-API设计文档.md)，实现流程详见[详细设计](05-详细设计文档.md)。
