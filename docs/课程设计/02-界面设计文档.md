# 市政公司统一权限管理系统——界面设计文档

版本：6.0；日期：2026-10-27。

## 1. 目的与交互原则

本文规定页面信息结构、路由、表单、权限入口、状态反馈和页面间协作，作为前端及交互评审依据。接口字段与错误码见 [API 设计](03-API设计文档.md)，业务规则见 [需求分析](01-需求分析.md)，组件与事务见 [详细设计](05-详细设计文档.adoc)。

界面使用统一应用外壳，减少页面切换造成的上下文丢失；清楚区分“角色的操作定义”“员工的角色分配”和“员工该角色的管理范围”。前端只呈现权限与提供反馈，不能代替后端鉴权。

| 原则 | 交互约定 |
| --- | --- |
| 信息优先 | 页面标题、主要对象、筛选与结果按层次组织；名称为主，编码、工号和请求号为辅助信息 |
| 权限可理解 | 菜单按具体管理操作出现；可维护状态与可查看状态分离，不以管理员名称一次性开放所有入口 |
| 保存可预期 | 编辑草稿与持久化结果分离，点击保存才提交；取消或关闭不保存 |
| 影响明确 | 共享角色修改提示影响所有持有者；员工范围修改仅作用于目标员工；完成离职明确提示集中撤权 |
| 结果可信 | 不把网络失败显示为无数据，不把鉴权允许显示为外部业务执行成功 |

## 2. 导航、布局与路由

菜单顺序为：**我的应用 → 工作台 → 组织管理 → 用户与授权 → 角色与权限 → 业务系统 → 鉴权日志**。侧栏、顶栏和内容容器跨页面保持一致；应用功能页属于“我的应用”，不使用另一套页面外壳。

| 页面 | 路由 | 入口条件 | 主要内容 |
| --- | --- | --- | --- |
| 登录 | /login | 无有效登录要求 | 账号、密码、登录结果 |
| 我的应用 | /portal | 已登录 | 当前有效应用卡片、准入入口 |
| 应用功能 | /applications/:id | 已登录且应用准入通过 | 模块、功能点及操作鉴权 |
| 工作台 | /dashboard | user.read | 范围内人员与部门、允许查看的目录统计 |
| 组织管理 | /organizations | org.read | 公司—部门—操作表、新增与修改表单 |
| 用户与授权 | /users | user.read | 人员筛选、分页、角色与范围、离职入口 |
| 角色与权限 | /roles | role.read | 共享角色卡片及两类权限编辑 |
| 业务系统 | /apps | app.read | 共享应用编码、启用状态、权限数量 |
| 鉴权日志 | /logs | 系统管理员 GLOBAL audit.read | 全平台认证／鉴权查询及归档 |

根路径和未知路径导向我的应用；未登录访问受保护页面导向登录。已登录但无管理页面权限时提示拒绝并返回我的应用。隐藏菜单不取消路由或接口的权限检查。
普通员工无管理授权时只看到我的应用；公司领导、部门经理、项目经理的导航取决于操作权限和员工范围，不设置额外的审计员身份。

布局使用标题、卡片／表格、标签和辅助文本；宽表格在自身容器横向滚动。状态同时使用文字与颜色，不能仅靠颜色区分允许与拒绝。表单控件具有标签，错误反馈使用可感知的提示区域；这些是交互要求，不构成无障碍认证结论。

## 3. 登录与个人应用

### 3.1 登录

账号输入接受用户名、工号或手机号，密码为遮蔽输入；界面不要求用户预选账号类型。提交期间禁止重复登录，失败显示服务端 message。不得在提示中显示密码或完整令牌。
登录成功保存会话令牌并读取个人身份与授权；令牌存于 sessionStorage，退出时调用退出接口并清理本地身份。会话失效或账号停用提示重新登录。

### 3.2 我的应用与应用功能

应用卡片只列有效授权应用。零个应用显示无可用授权提示；多个应用供用户选择；仅一个应用时执行一次准入校验后进入，避免刷新身份时重复自动跳转。
进入应用必须再次请求准入，不能仅根据旧卡片放行。准入后呈现模块、功能说明及操作按钮；allowed=false 的操作不可触发允许态操作。操作按钮调用鉴权接口并说明允许／拒绝，不宣称完成真实业务 CRUD。
授权回收、会话变化或目录不可用时清理过期功能内容，提示原因并引导返回。快速切换模块时迟到响应不得覆盖新模块；离开页面后的异步结果不得恢复旧视图。

## 4. 工作台与共享目录

工作台展示组织用户、角色、系统目录和操作权限统计，并提供用户授权入口；部门与日志数量作为辅助信息。人员／部门统计按 user.read 范围，目录和日志数值受对应查看权控制，无查看权显示 0。
角色卡片呈现名称、说明、启用状态、范围内关联用户数和角色权限数。业务系统卡片呈现名称、编码、启用状态和权限数，说明目录／鉴权交互不等于真实业务系统功能。
这两个目录不提供通用新增、删除或启停按钮。

## 5. 组织管理

### 5.1 展示与入口

主表固定为**公司—部门—操作**。公司合并单元格，编码放在名称下作为辅助信息；无部门的公司显示“暂无部门”。不显示上级部门、上级公司或部门树。

| 操作 | 入口条件 | 提交语义 |
| --- | --- | --- |
| 新增公司 | GLOBAL org.write | POST，提交编码与名称 |
| 修改公司 | GLOBAL org.write | PATCH，仅提交编码与名称 |
| 新增部门 | 某公司 COMPANY 或 GLOBAL org.write | POST，提交所属公司、编码、名称 |
| 修改部门 | 返回对象 writable=true | PATCH，仅提交编码与名称，不携带归属 |

部门范围管理员不能新增部门。公司／平台范围管理员新增部门时，公司下拉只列可维护公司。默认部门经理和项目经理无 org.write，可由平台按角色统一配置；入口不因岗位名称自动出现。

### 5.2 表单与反馈

编码长度上限 100，名称上限 191，均为必填且非空白。修改时预填原编码和名称；新增部门才显示公司选择。保存期间禁用保存，取消关闭编辑；成功后刷新组织列表，失败保留输入与错误。
接口允许只提交一个字段的 PATCH，界面可以提交两个编辑字段；不得提交 parentId、companyId、enabled 或负责人字段进行组织修改。无移动、删除或停用入口。

## 6. 用户与授权

### 6.1 筛选、表格与分页

筛选顺序为公司、部门、关键词、查询、重置。关键词匹配姓名、用户名、工号或手机号；切换公司清空部门并回到第一页，部门变化和提交关键词也重置页码。公司和部门选项来自范围内有人员的组织。
表格依次展示员工、工号、电话、所属组织、岗位、当前角色、账号／人员状态和操作。缺电话或组织显示“—”，无角色显示“未分配角色”；工号和电话按字符串展示。
每页 20 人，接口页码从 0 起，界面从第 1 页展示；显示总人数、当前页／总页数和上一页／下一页。边界或加载期间禁用翻页。无匹配结果与加载、错误使用不同反馈。
同一页面发起多个查询时，仅最近请求的结果可更新列表及筛选项，避免先发后到的响应覆盖新条件。

### 6.2 人员操作入口

| 入口 | 显示与可用条件 | 影响对象 |
| --- | --- | --- |
| 分配角色 | 无 GLOBAL management.grant，且目标 managementActions 含 user.roles；已离职时禁用 | 目标员工的业务角色集合 |
| 分配角色与管理范围 | GLOBAL management.grant；目标须 ACTIVE | 目标员工的角色集合和各角色范围 |
| 离职交接 | 目标 managementActions 含 handover.start 或 handover.complete | 目标员工交接与撤权流程 |

managementActions 只是允许尝试的操作，权限子集、人员状态和最后管理员保护仍由保存接口判断。角色目录编辑不放在员工弹窗中，避免误以为更改只影响一个员工。

## 7. 角色与范围编辑

### 7.1 业务角色与共享权限选择

角色选项或业务权限选项先完整加载，再在客户端筛选显示。勾选状态独立于过滤结果，保存提交完整选择集合，不能因搜索隐藏而撤销其他项。显示已选择数量；加载未完成或提交期间禁用保存。
取消不提交；保存成功关闭弹窗并刷新数据；失败留在弹窗显示错误。清空集合表达撤销全部，仍受后端保护。
角色页分设“业务功能权限”和“管理操作权限”，都要求 GLOBAL role.permissions；文案说明修改影响所有角色持有者，不修改各员工管理范围。审计、共享权限和管理范围配置等平台专属操作只可分配给系统管理员角色。

### 7.2 员工角色与管理范围弹窗

弹窗标题显示目标员工。内容分为两个明确分区：

1. **① 分配角色**：选择员工所持角色。
2. **② 设置管理范围**：增加或移除范围草稿行，范围的角色只能来自上方已选角色。

| 范围类型 | 可用角色 | 表单显示 | 含义 |
| --- | --- | --- | --- |
| 全平台 | 系统管理员 | 不显示公司或部门 | 全平台，包括无部门人员 |
| 指定公司 | 其他角色 | 公司 | 该公司全部部门及人员 |
| 指定部门／项目部 | 其他角色 | 公司＋该公司下的部门 | 精确部门，不包含任何隐含子部门 |

同一角色可以有多行。更换范围清除不适用字段，更换公司清空部门，撤销角色同时移除其草稿范围。增加范围只改变草稿，不立即调用保存接口；全部角色与范围点击“保存全部更改”统一提交，取消丢弃全部草稿。
只分配角色而没有范围时，该角色可产生业务功能权限，但没有管理权。部长和副部长使用部门经理；项目经理、项目副经理和项目总工程师使用项目经理，范围按员工分别配置。例如同一角色的两人可分别管理第一项目部与第一、第二项目部。

## 8. 离职交接

交接弹窗展示目标人员状态、账号状态、当前角色、可用系统和最近变更记录。不存在记录时展示在职；关联人员不在查看者范围内时显示“范围外人员”，不暴露被遮蔽的 ID／工号。

| 状态 | 表单／操作 | 反馈与限制 |
| --- | --- | --- |
| EMPLOYED | 有 handover.start 时填写接收人工号、负责人工号、预计日期、交接说明及可选 OA 单号 | 说明发起保留授权，接收人不自动获得权限 |
| HANDOVER | 展示交接资料；有 handover.complete 时填写完成说明并勾选明确确认 | 显著提示将撤角色与范围、停用账号、撤销会话 |
| DEPARTED | 展示完成时间和说明、保留记录提示 | 不提供重新发起、回退或恢复账号按钮 |

接收人和负责人上限 100 字符，交接／完成说明上限 1000，OA 单号上限 200；预计日期为日期控件，不设置必须晚于今天的要求。完成确认在协议中发送字符串 "true"。
保存失败保留表单；成功后关闭并刷新人员列表。用户和历史记录保留，不用删除员工代替离职处置。

## 9. 鉴权与认证日志

### 9.1 筛选与游标

日志页使用同一外壳。筛选区包含用户 ID、账号、系统编码、结果、事件类型、开始／结束时间和归档状态。账号与系统精确匹配；开始含、结束不含。时间输入为本地时间，提交转换为 UTC，记录列明确标注 UTC。
点击查询建立已提交条件，每批 50 条；“加载更多”沿用该条件与服务端游标。尚未提交的筛选草稿不能改变后页条件。重置清空条件并重新查询；不提供页码跳转或“总共有多少条”的精确统计承诺。
显示已加载条数。首屏无结果显示空态；加载期间禁止重复查询和归档；后页失败保留已加载结果与错误。到达末尾提示重新查询可获取新记录。页面卸载后迟到响应不得恢复内容。

### 9.2 结果呈现

结果列为 UTC 时间、账号／用户 ID、事件／系统、结果、原因／请求号及归档状态。未知账号显示“未识别”；无应用码时可展示请求路径。用文字标记成功／拒绝和已归档／未归档。
错误展示 message，查询错误可附 code；API 客户端保留 code 和 requestId 供逻辑判断及定位，界面不保证每个错误位置均直接展示请求号。事件中的请求号与接口外层请求号必须按各自语义使用。

### 9.3 归档

归档使用独立展开区域。截止时间为必填，确认提示必须包含：作用于截止时间前全部未归档日志、不受上方筛选限制、每批最多 1000 条、不删除数据。
点击“确认归档本批”后禁止重复提交；成功展示本批条数，hasMore=true 时提示可继续，关闭归档区并重新查询列表；失败保留错误。界面不将逻辑归档称为导出、删除、压缩或冷存储。

## 10. 通用反馈与身份同步

| 场景 | 反馈规则 |
| --- | --- |
| 初次加载／查询 | 显示加载态；不能以空态替代未知结果 |
| 空数据 | 根据页面说明无授权、无匹配人员或无符合条件的日志 |
| 保存成功 | 明确提示成功，刷新对应资源；不推断其他独立业务已执行 |
| 业务校验失败 | 展示服务端 message，保留可修正输入，按 code 区分规则 |
| HTTP 401 | 非登录请求清理失效身份并提示重新登录 |
| HTTP 403 | 不显示成功；刷新身份及授权，失去页面权限则返回我的应用 |
| 网络或响应格式异常 | 展示连接／格式错误，不当作业务允许，也不自动重放写请求 |
| 取消／关闭 | 关闭草稿，不保存；危险操作必须经过明确提交 |

身份在受保护路由进入时读取，并按 3 秒间隔及窗口聚焦刷新；管理授权集合变化时卸载旧管理视图再读取，失去权限返回我的应用。刷新周期只控制显示反馈，安全决定仍由每个后端请求完成。

## 11. 原型约定

[离线原型](../原型/06-界面原型.html)使用虚构员工与内存状态，不调用真实认证或管理接口；刷新／重置恢复示例状态。原型用于表达导航、角色范围草稿、应用准入、日志筛选和归档的交互。
原型中的登录失败、未认证示例只生成虚构事件，不表示访问真实账号。Vue 页面通过 API 取得业务数据；两者使用一致的角色、组织、权限和操作概念。

## 12. 界面验收准则

| 标识 | 场景 | 预期行为 |
| --- | --- | --- |
| UI-01 | 切换我的应用、日志与管理页 | 同一外壳与导航顺序，应用功能页保持我的应用高亮 |
| UI-02 | 普通员工或局部管理员直接输入管理路由 | 按具体操作拒绝，不因菜单隐藏而省略后端检查 |
| UI-03 | 切换公司、部门与快速查询 | 部门联动和页码重置，旧响应不覆盖新结果 |
| UI-04 | 筛选权限后保存 | 隐藏选择保留，完整集合提交 |
| UI-05 | 切换范围类型并取消 | 字段条件显示正确，草稿不隐式保存 |
| UI-06 | 修改组织 | 只提交编码名称 PATCH，不出现父节点或归属编辑 |
| UI-07 | 完成离职 | 有明确影响说明和确认，失败不显示成功 |
| UI-08 | 日志查询后修改未提交草稿再加载更多 | 后页仍使用已提交条件；新查询重置游标 |
| UI-09 | 日志归档 | 明确全局截止时间语义、分批且不删除；成功后刷新 |
| UI-10 | 会话失效、权限变更、页面卸载 | 清理过期身份／内容，不恢复迟到的受限视图 |
| UI-11 | 窄屏与键盘操作 | 表格容器滚动，基本控件可聚焦、标签明确、状态有文字 |

以上是交互验收要求，不记录实际测试或浏览器验证成绩。
