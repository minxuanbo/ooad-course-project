### 2.1 实时鉴权与日志的明确验收场景

下表为本次需求补充的预期验证方法，不表示本轮已执行业务验收；两套实现后续均应满足。

| 需求 | 场景 | 预期结果 |
| --- | --- | --- |
| R08、R09 | 同一登录身份先成功调用API，管理员撤销唯一有效授权并提交，原身份再次调用 | 无需重新登录即拒绝，不依赖页面刷新、令牌过期或缓存周期 |
| R09 | 撤销角色A，但角色B仍有效授予相同API | 保留B提供的能力及当前范围，不误撤全部权限；授权事务回滚时不部分生效 |
| R12、R15 | 停用/调动提交；或管理写等待根锁期间被撤权 | 原身份不能继续管理或沿用旧范围；取得根锁后按最新事实重验并拒绝失权写入 |
| R16、R20 | 分别制造登录成功/失败、未认证访问和鉴权允许/拒绝 | 事件信息齐全，同一安全事件不因多层采集重复；未知主体可空，无原始手机号、凭据或查询串 |
| R16 | 组合筛选并连续读取多个游标批次，期间插入新日志 | total为同条件同快照总数，不等于页长、不随翻页缩小；刷新新快照后才纳入新事件 |
| R16 | 日志读取者被撤日志权限，或部门账号被误授日志API | 下一批仍重新鉴权；无日志权或非共同根即拒绝，不以旧游标绕过 |

当前产品本地初始化命令只维护在[后端说明](../backend/README.md#3-新项目本地初始化与运行)。验收探针拒绝非空库并核对实际datadir，失败不自动清库。隔离环境、原始资料与测试夹具分别标注；报告记录源提交、JDK/MySQL版本、命令、结果及限制。未来代码归类或DDD阶段须重跑受影响真实回归，不能沿用T13数字。

旧容器JaCoCo脚本见[现场说明](../deploy/现场运行JaCoCo.md)，待新服务器方案适配；当前本地Maven配置保持，用户确认当前不作为阻塞，配置保留。功能test通过不等于verify覆盖率达标，不通过时不得用skipTests、排除类或旧exec冒充。无Docker环境时不宣称镜像/Swarm验收。
