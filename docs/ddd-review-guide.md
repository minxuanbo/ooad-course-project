# DDD设计逐项审核

本轮只审核设计和文档，尚未开始DDD编码。先读[DDD设计](ddd-design.md)，再看[完整图集](design/README.md)；图名中的DDD目标不是实现完成声明。结构化基线已合入main，设计分支codex/ddd-design从a4275be建立。

| 顺序 | 审核点 | 对应位置 |
| --- | --- | --- |
| 1 | 同仓库、同API/SQL/前端，完整策略互斥，三个启动入口与支撑端口不漏切换 | DDD设计第1—3章；两张包图 |
| 2 | 六实体聚合与标识引用、规则归领域，User/Role不加载全公司对象图 | 第4章；人员、角色、资源、部门及系统类图 |
| 3 | Repository只有领域输入输出，DomainPage元素为领域类型，日志复杂查询明确用Gateway | 第5章；查询、总览、日志类图 |
| 4 | 所有相关写共同根锁、锁后重鉴权、最新修改后的单人K及失败全回滚 | 第6章；维护者类图 |
| 5 | 双入口/本地口令、映射及异常翻译；final/record显式构造、后续注解独行 | 第7章 |
| 6 | 初始化业务不复用结构化服务，原始资料、五角色、来源、墓碑、幂等及回执保持 | 第8章；导入、首次授权类图 |
| 7 | 差异顺序图没有共同Controller/Bearer/日志/根锁/K/提交；源状态及省略边界清楚 | 第9章；六组12张差异顺序图 |
| 8 | 设计认可后才编码；共享契约、架构检查、真实数据库/并发/回滚与双策略验收顺序明确 | 第10章；评审记录 |

本轮新增2张包图、15张类图和12张差异顺序图，各有PNG和可编辑SVG；保留已批准结构化身份类图，原完整身份顺序图不再作为当前设计。图集给出逐图范围，不能把单张图省略的成员误认为系统没有对应职责。

建议反馈时写出章节/图名、需要调整的业务或依赖关系、预期方向。用户审核通过后再创建实现任务，不在本轮提前放DDD类、空实现或假配置开关。
