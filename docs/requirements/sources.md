# 需求来源

本文按来源类型记录依据；现行行为以[需求说明](../requirements.md)为准。原始材料、课堂要求和用户后续选择分别标明，避免把示例代码或旧实施状态当作业务要求。

## 1. 老师要求

以下摘录来自第一轮录音整理纪要（2-9.m4a，约25分13秒），属于结构化整理，并非逐字转写。原DOCX、录音及个人评分留在本地，不提交。完整历史复核材料见[原始复核](../history/rbac-rectification/RBAC检查记录复核说明.md)。

### 一、ER图与需求

ER图应使用标准符号并只表达核心对象。User、Role、Permission及两组多对多关系必须保留，日志、登录凭证、业务功能点、OA模块等非本轮核心内容不应进入ER图。

公司可并入层级Department；部门扩展用于一万多名用户的分部门管理。管理员由角色中的管理权限决定，并以同部门/下级部门范围限制授权对象，不需要管理员属性。

权限应具体化为菜单和按钮树；API需单独建模并与菜单/按钮建立关系，以便从用户角色推算可调用API。下一阶段需覆盖本权限系统和课程管理系统两个系统。

统一登录标识、离职交接、会话、角色版本和复杂业务模块不属于本轮权限系统核心需求，应删除。当前阶段采用令牌登录，会话不写入数据库。

### 二、API设计

当前API直接由需求文档生成，结果混乱且缺少分页、部门分组、搜索等场景。应先做出正确的界面原型，再由界面生成API并逐项审核。

人员列表面对一万多名用户，必须按部门显示并支持搜索、分页；只返回全部用户的接口不可接受。API说明应由需求文档补充并作为后续代码生成契约。

### 三、代码与架构

后端代码缺少模块和分层控制，生成时未审查可读性，并使用JDBC直接写SQL。应明确Controller、Service、Repository结构、模块边界及技术栈。

下一轮必须使用课程规定技术，特别是Spring Data JPA和AOP；AI默认倾向旧技术，需持续检查和校正输出。

### 五、整改重点

重画核心ER图；删除会话、凭证、功能点、离职交接等超范围内容；补部门和多系统；建立菜单/按钮—API关系；重做分页、搜索和部门分组接口；按JPA和AOP重构代码。

课堂补充图片进一步要求人员调动、部门范围授权、菜单/按钮与API关联、REST路径、分页搜索，以及声明式事务、JPA、AOP和真实CloneFactory。“针对用户的权限”采用选人后授撤角色与验证实际访问变化实现，不增加直接用户授权模型。

老师统一身份八项契约来源为[Apifox共享文档](https://s.apifox.cn/775094d6-9f5f-4b75-9600-2332c43948d3)，业务审计另属独立分组。课程对象权限以老师生产实现为界，文档声明但未实现的Controller列入[接入限制](../course-integration.md#6-老师业务的已知限制)。

服务器部署参考老师course-project-mgt/deploy；CPU监控参考用户指定的spring-fundamentals/4. SpringAOP/conf/prometheus及conf/docker。具体来源快照、2秒公式与配置覆盖关系见[监控设计](../../deploy/monitoring.md)。

- 员工表“员工信息”有 10,000 条人员记录，六列为姓名、用户名、分公司、部门、岗位、电话号码，均无空值；用户名和电话各 10,000 个不同值，姓名仅 7,859 个不同值，不能按姓名定位唯一人员。源表没有另设标题为“工号”的列；按2026-11-08用户明确的同一概念，“用户名”列即工号来源，“电话号码”即手机号来源。原表没有口令哈希、有效状态或人员角色关系；旧初始化生成的口令/状态/授权不是老师原始值。
- 部门表“部门信息”有 111 个不同节点，唯一根为“总公司”，无缺失上级、无环且连通，最大三级。10,000 人均能唯一归属：244 人按部门原名、9,756 人结合分公司前缀匹配。110 个节点有直属人员，根节点没有；根负责人对应的员工在“公司领导”，不能按姓名自动改归属或提权。导入后须核对真实父子外键和来源映射。
- 权限表含 18 个系统、115 个模块、359 个功能点；五类业务角色是系统管理员、公司领导、部门经理、项目经理、普通员工。没有 HTTP 方法/路径，也没有“某员工拥有哪些角色”的数据。“全部”是功能操作表述，不等于跨部门范围；“部门经理”对后台角色管理/范围配置为“无”，不能按岗位自动视为本项目部门管理员。
- 三份工作表的声明范围均为 `A1`，不能依此截断读取；权限表有 134 个合并范围，系统/模块分组须按实际合并范围恢复。权限表 `H117` 为 `view/新增`、`G310` 为 `view/编辑/审批`、`I340` 为空；另有“查看本人”“编辑本人”。选用条目时记录转换或拒绝理由，不擅自把空白当允许或丢弃本人范围。
- 清单中的日志、密码重置、双因素认证及大量业务模块不因出现在原表就全部恢复。鉴权日志仅按最新用户要求复用最小能力；表中培训功能提到课程，不等于后续课程系统已确认或完成。别组 HTML 不作为需求或验收依据。
