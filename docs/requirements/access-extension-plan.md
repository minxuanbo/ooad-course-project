## 1. 应用目录与待接入状态

原权限Excel实际为18系统、115模块、359功能点；前17项为108模块、338功能点，末项“系统管理后台”为7模块、21功能点。后续按用户补充的完整18项准备目录，不能只导入前17项。保留本RBAC与原表“系统管理后台”是不同业务系统的既定语义，再加课程系统，共20个目录项；18项为待接入，RBAC和课程已有真实接入。

拟为应用增加独立的接入状态PENDING/CONNECTED，enabled继续表达业务启停。待接入项允许维护权限树和计划授权，任何身份登录、短码/API判断都必须检查接入状态；待接入不产生业务通行能力。正式接入须配置真实方法/模板、权限映射和操作目录，并通过独立验收后切换状态，不以出现于下拉框代替接入。

独立初始化从原件只读提取系统、模块、功能和动作，并保留来源单元格/摘要及稳定编码。MENU用于导航，BUTTON用于明确动作；API类型仅在有真实非空完整映射时配置。不生成模拟业务Controller或假API，不丢失“查看本人/编辑本人”的限定，不将“全部”作为跨部门或跨系统通配符；空白不授权，原表view保留规范化记录。重复执行须校验来源及回执，不重置后续维护。

## 2. 角色来源与管理级别分离

页面统一呈现8个预置角色：五个基础管理角色及课程接入配置登记的教师、学生、课程管理员。持久化拟区分SYSTEM_BUILTIN、APPLICATION_PRESET、DEPARTMENT_CUSTOM及已有GLOBAL_CUSTOM；分类不能从名称猜测。

只有五个基础角色保留managementLevel=5/4/3/2/1。三个课程应用预置角色级别为空，应用归属及稳定编码来自接入配置；通用RBAC不增加Teacher/Student实体、教师标记、课程编码白名单或业务继承。管理员兼课程管理员仍通过显式两套角色关系表达。

部门自定义角色拟增加ownerDepartmentId，要求有效所属部门；共享全局角色的该字段为空。角色代码继续全局唯一、创建后稳定；既有全局自定义角色保留原分类及关联，不批量猜测部门。角色可跨应用选权，Permission—ApiResource同应用约束不变。

## 3. 部门分配规则

推荐首版由系统管理员建立部门角色、确定所属部门及权限，所属部门及上级范围内获准领导负责分配/撤回。不向领导开放全局角色选权、启停或归属调整，避免修改共享角色间接改变本人、同级或上级权限。若后续要求领导自行选权，须另行定义可授权限上限和受影响成员保护。

分配同时满足实际操作API、操作者部门子树、角色适用部门子树、本人/同级/上级保护及完整权限子集。待接入项的计划授权子集与运行时通行集合分开计算；计划授权不绕过接入门禁。基础角色仍按原授予级别规则；应用预置和全局自定义角色仍仅合格根管理员调整。部门自定义角色不提升级别、不冻结持有人。

整体保存沿根锁、锁后重新加载主体/目标/角色/权限，只校验新增与删除差集；无权改变的现有项原样锁定保留。人员调动除检查原/目标范围外，同一事务移除不再适用的部门角色；再次调回不自动恢复。实时鉴权复核角色部门归属，部门删除检查所属角色，防止残留关系扩大权限。

部门角色列表及成员数只返回操作者可见范围，不泄露全公司人数。管理员仍可相互管理，写后同一可信根至少保留一名启用、有效五级且独自完整覆盖K的人员。

## 4. 契约与实施边界

本轮机器契约仅新增现有GET /api/users的departmentScope、roleId查询参数和日志clientIp字段，仍为37操作、31路径、71 Schema、K17。上述角色类型、ownerDepartmentId、接入状态暂不加入已实现OpenAPI Schema，避免客户端误以为已经可用。后续确认实施时再同步请求/响应、首次SQL、双策略、界面及相应接口文档。

表结构演进必须保留当前人员、授权调整、原库/卷及历史日志，不以重复初始化或自动DDL覆盖。项目仍只交付新库首次SQL，正式部署数据兼容方案需要在实施前单独核对。本轮不写Apifox、不部署、不修改老师原始前端或外部设计材料。

后续开放部门角色页时，列表/成员/可分配候选都须按组织范围在数据库过滤后计数，定义写入与分配入口分开；不能直接移除现有共同根检查来开放所有角色。领导只负责已核实部门角色的分配/撤回，权限定义及启停先由管理员维护，避免通过共享定义间接改变本人、同级或上级权限。调动须在原有双范围与级别保护下，于同一事务撤下不适用的部门角色，回调不自动恢复；实时鉴权同时验证归属，部门删除须处理角色归属。已有全局自定义角色保留原分类，不能猜测所有者或强行迁为部门角色。
