# 首次登录渲染修复与匿名记录核对（2026-11-24）

用户报告登录成功后首页空白，刷新才出现数据，同时发现没有主动操作也出现“未认证访问”。基线cb04cd1；本记录区分界面缺陷、正常身份拒绝及实际发布状态。

## 白屏原因与修改

在正式版本用新的Chrome会话从登录表单进入：登录、本人能力、总览及最近活动接口均200，但首页和右上刷新按钮不可见，控制台出现Vue渲染异常；浏览器刷新后正常。可控HTTP响应下的真实Vue/Router测试同样复现，原实现三项渲染场景均RED。

PageActions通过Teleport向#page-actions投放操作。登录页切换到工作区时，标题区和首页在同轮DOM挂载，立即解析目标会遇到尚不存在的容器，继而中断子页面渲染。修复仅为使用Vue3.5支持的defer，等本轮挂载完成再定位；菜单布局、路由结构、身份读取、业务API和授权规则保持原样，没有额外查询或强制刷新。

此前性能浏览器脚本先取得有效JWT再直达工作区，验证了菜单读取和耗时，未覆盖从登录表单到首个工作区的DOM挂载。本轮补充此边界，不把此前18次菜单读取计为首次登录渲染通过。

## 截图时段的匿名访问

按鉴权库及Nginx访问记录只读核对，时间均为北京时间：

| 时刻与请求 | 实际记录 | 能确认的含义 |
| --- | --- | --- |
| 06:35:36.820 GET /api/me | 401 SESSION_INVALID | 服务端会话校验失败；会话过期、退出或进程重启后的旧会话均可能如此，单条原因码不能继续细分 |
| 06:26:18.303/355 HEAD及GET /api/roles | 401 AUTHENTICATION_REQUIRED | 没有可识别的Bearer身份；来源与上一行不同。正式前端API客户端没有HEAD请求逻辑，不能将其直接算作用户点击 |
| 06:15:59及06:25:50的/auth/me | 401 AUTHENTICATION_REQUIRED | 另一个来源的无身份请求，其中含HEAD/GET；现有记录不能确认具体操作人或是否为链接预览/探测 |

页面打开、恢复或导航时会自动读取本人能力，不要求用户点击业务按钮。旧token存在时的一次自动请求就可能留下拒绝；渲染回归补验该请求401后清理本机会话并进入登录页，不循环发送。身份认证未通过时不能把请求认作某个员工，因此显示未识别身份；不通过解码未验证token补认用户。

白屏复现中的接口为200，和上述401的成因分别记录。本轮没有删除匿名日志、停记拒绝事件或改变鉴权规则。来源分析只保留必要摘要，不在文档公开IP；HEAD/GET与浏览器User-Agent不足以确定真实人或具体工具。
