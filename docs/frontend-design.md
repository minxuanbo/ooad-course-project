# 前端概要设计

版本：1.7；覆盖整个RBAC管理端的目标交互，依据[需求](requirements.md)、[API契约](api-contract.md)与用户原型反馈。本文说明界面职责和规则；本阶段真实验证结果另见验收记录，不由设计文字代替。阶段3第六轮交互见[唯一原型](../prototype/index.html)及[评审记录](prototype-review.md)，部门按层级显示并明确人数口径；阶段4正式接口与Vue实现同步；R28中的18系统仅保留于离线原型，正式页面只管理RBAC自身。

## 1. 目标与现状

目标使用Vue3/Vite构建共享前端，后端structured/ddd切换不改变页面、请求和授权语义。阶段4frontend包含登录、总览、部门、人员、角色、资源与日志页面，使用真实HTTP；原型仅作为获批交互参考。完整前端始终属于项目设计范围，状态差异不删减设计内容。

## 2. 信息架构

| 页面/区域 | 目标职责 | 可见及可操作条件 |
| --- | --- | --- |
| 登录 | 单一工号或手机号+口令表单，提交状态、错误和重试 | 匿名可见；成功须后端管理准入，普通员工不进入管理空间 |
| 共用外壳 | 当前身份、已授权导航、全局错误通知、退出 | 有效登录；部门账号可进入外壳，不强跳日志或显示无权全局目录 |
| 总览 | 范围内人员/启用/停用/组织数量、下级分布、获准入口 | 当前人员管理范围；最近鉴权活动另需日志API及共同根 |
| 部门管理 | 部门目录、新增下级、改名、删除空部门 | 系统管理员全公司；局部管理员可在本人/下级下创建，只改删严格下级；每次实际鉴权，无层级调整 |
| 部门与人员 | 仅可见部门树、搜索/状态/分页表、人员动作 | 对应实际查询API及本人部门子树 |
| 人员角色抽屉 | 当前角色、候选搜索/分页、勾选草稿、确认保存 | 当前查询/候选/写入各自授权；不能以角色名称猜可授予范围 |
| 停用与调动对话框 | 目标摘要、影响确认、目标部门选择与失败反馈 | 具体操作权限；原部门和目标部门均在范围，受自身/管理员限制 |
| 角色与权限 | 角色列表、空权限新建、改名/启停、权限独立选择 | 共同根与每项实际操作权限，人员管理员不读取全局角色目录 |
| 资源与API映射 | 本系统权限树、API候选、完整已选ids、必要状态维护 | 共同根与具体目录/写API；不增加通用系统/资源CRUD |
| 鉴权日志 | 筛选、快照total、逐批加载、刷新与错误 | 实际日志GET获准且共同根；部门账号隐藏入口、直接请求仍403 |

权限编码用于显示标识，不作为后端授权凭证。同一API可以由其他有效权限映射覆盖，界面不能强制只有固定code或指定角色名才显示功能。GET /me返回最新routes及globalScope供界面显示实际操作；日志不使用额外GET探测入口，也不读取无关部门树。

## 3. 核心交互

### 3.1 登录与会话

account按字符串保留前导零、仅trim首尾；password不trim。工号和手机号不分成两个账号或两个口令。提交时禁重复点击，失败显示统一业务message；未知/错口令/停用/歧义均沿401 LOGIN_FAILED，不在页面区分用户存在性。403管理准入失败不进入成功页面；网络/500可重试。凭据不进入URL、日志或通知。

登录后读取本人及有效权限，显示可用导航；无日志权限的部门管理者仍可正常到达管理外壳。401清理当前身份并回登录；403保持已登录状态但移除或禁用失效操作，提示刷新。请求响应需绑定发起时身份，账号已切换时丢弃旧响应。

### 3.2 部门人员与授权

树只展示返回范围，后端投影的可见根parentId=null不据此认定全局管理员。部门选择包含后代，q搜索姓名/工号，状态筛选与page/size统一生效；切换筛选重置第0页，total来自同一条件，空结果与越末页分别显示。人员操作一律用内部id，不以重名或手机号定位。

人员列表同时展示“职位”和“已授角色”。职位来源为原始岗位等人事资料，只读，无职位编辑或职位调动；岗位文字不参与运行时鉴权。角色摘要应包含停用项，多角色保留完整摘要入口，实际分配仍独立读取完整集合；后续API需增加position及轻量角色摘要，不能对每行发一次角色查询形成N+1。

授权抽屉先读取当前角色，再独立分页查询可授予候选；当前已有但不可新授的角色须保持完整显示，不能用当前候选页替代已选全集。跨页选择保持草稿，取消不写库，确认才PUT整体ids；[]为清空，须明确确认。失败保留可理解的草稿与错误，不显示部分成功；遇并发冲突可重新加载核对。

候选同时受R23级别上限、全部有效Permission子集和部门范围约束。项目经理的级别上限为项目经理/普通员工，但候选不保证两者齐全；原表业务权限不逐级包含，缺少目标角色任一有效权限即不可授。部门经理也不会因管理级别取得公司领导资格。名称变化不改变级别，自定义角色默认仅管理员可授。已存在但当前不可再授的角色不能被静默删掉，提交时须重新整组校验。

停用对话框只提交enabled:false，不提供本轮未约定的恢复、创建或删除人员。调动选项来自可管理部门树，确认显示原/目标部门；后端拒绝双范围越界，前端不通过调整隐藏字段绕过。成功后重新读取行状态与授权，调动不自动按新岗位改角色。

R27同时约束目标：非系统管理员对本人、同级和上级只读，按钮禁用并解释原因；分配、停用、调动都应由服务端独立复验。把下级授为本级后，后续操作立即采用新级别保护。职位不用于级别判断。

部门目录显示直属/含下级人数及本人标记。“新增下级”父级仅本人和下级可选且符合R24类型：总公司建分公司/部门/项目，分公司建部门/项目，部门仅建项目，项目按钮禁用。切换父级同步收窄类型选项，服务端仍应独立校验；创建后不提供父级编辑。“修改名称”仅改名称。“删除”仅空部门可用，有人员或子部门说明原因，提交前二次确认，根不能删除。局部管理员本人部门不可改删，上级和平级不进入维护范围。成功后重读树、总览及相关列表，不伪造人事调动。

目录采用子树连续排序与逐级缩进，工程管理部的项目应紧跟在它下面；搜索保留可见祖先路径。人数列明确为“直属人数”“总人数（含下级）”，说明停用账号也计入人数，父部门总人数已含项目人数。统计遵循需求3.4，不能为消除视觉误读改变人员归属或把父子行当独立分类相加。

### 3.3 角色与资源

角色列表按名称/编码、状态与分页查询，空权限新角色创建后显式选权。权限checkbox独立，导航补祖先仅为展示，不加入待保存ids；父菜单不自动勾选子权限。改名、启停及替换权限明确共享影响，保留原型中取消/重新读取的草稿语义。

四个基础角色的首次原型数据按Excel对应列预置业务操作及必要祖先菜单，管理员打开各系统时应看到实际已选集合。首次显式授予菜单与后续独立勾选分开；重读页面不重新套用原表，修改后保留草稿和保存结果，只有显式重置恢复默认。普通员工获得业务权仍不产生本RBAC管理端准入。

资源页先加载必要目录才允许编辑；权限树仅维护parentId/type/enabled，API只启停，method/path/code/system归属只读。API映射候选按数据库分页，已保存ids完整读取并跨页保留；API反向引用由已批准查询结果组合，不新增泛化接口。树循环、跨系统、非法关联与最后管理员冲突显示400/403/409及requestId，不假装保存成功。

仅在R28离线原型演示中，资源页提供本RBAC与原表18系统选择；菜单/按钮、API、原表矩阵分别查看。矩阵支持功能/模块搜索和分页，保留五角色原文、来源行及未规定项。18业务系统未实现，API页显示空态，只演示RBAC跨系统控制能力，不编造URL；未来仅接入课程管理系统，其业务接口由课程项目定义。管理员选权按系统切换显示，完整draftIds始终保留，仅逐项勾选，不显示原表角色模板套用。新角色仍为空权限，矩阵查看不等于实际授权。“全部”仅为本行其他角色操作并集，无额外权限项；查看本人/编辑本人及缺失项处理沿R28。账号状态与角色状态明确分列/标注，停用角色不自动停用账号。

### 3.4 最小日志

筛选用户ID、工号精确值、系统、结果、事件与时间；时间输入转UTC，from含/to不含。首次查询形成快照，继续加载绑定同一筛选和limit，不把编辑后的筛选串接到旧游标。显示snapshot内total、已加载条数、更多状态，刷新清空游标重新查询。无归档、导出或变更历史按钮；部门账号无入口，手动访问仍由服务端拒绝。

## 4. 状态、错误与可用性

列表与表单分别具有加载、空、成功、失败及重试状态；等待时禁重复写，读取竞态采用请求序号或取消机制，卸载后不写回旧页面。错误可读并带requestId，键盘可聚焦输入、按钮和对话框，危险操作需清晰确认。窄屏表格可横向滚动，不截断关键确认信息。

角色权限/API映射编辑须明确区分“完整集合尚未读取”和“已读取的空集合”。403/500/网络失败应安全展示并提供完整重试，初始读取成功前不允许候选搜索、勾选或整体替换保存；候选读取成功不能证明原映射已读取。日志查询响应只确认其发出时的筛选/批量，期间修改工号、结果、时间或批量后仍须显示待查询，并阻止继续加载旧快照；重新查询成功才解除。未认证受控请求应显示UNAUTHENTICATED，保留同一次失败的requestId、401及安全原因，登录仍独立分类。

401回登录；400定位参数；403更新访问状态；404在已授权范围显示对象不存在；409说明重新核对或最后管理员保护；500保留安全错误及重试入口。前端隐藏按钮只是交互提示，真正的权限、范围、事务与完整K由后端逐次执行。

## 5. 实现与验收规划

页面到API的唯一操作索引见[API对照](api-map.md)。正式实现须先按新原型审核结果逐切片对接，不复制两套structured/ddd页面。共用前端契约测试验证身份切换、越权入口、分页/草稿/失败，以及相同HTTP契约；T13仅验收后端，不以原型或兼容页代替全量界面验收。原型已由PR #31合入；阶段4在独立分支实现，审核后再合并。

## 6. 页面、组件与状态归属

Vue页面按上述工作区归类；Modal、Pagination和CollectionEditor复用焦点约束、分页及完整集合编辑行为。

| 模块 | 主要组件职责 | 状态归属 |
| --- | --- | --- |
| 应用外壳 | 导航、身份摘要、退出、requestId错误通知 | 当前会话/有效操作信息全局共享，退出和401清理 |
| 登录 | 工号或手机号、口令、提交反馈 | account/password仅表单生命周期；不持久化口令 |
| 人员工作区 | 可见部门树、搜索/状态、分页表、行操作 | 当前筛选和page/size归页面，异步结果绑定身份与查询版本 |
| 人员角色编辑 | 当前角色、候选分页、已选摘要、确认 | savedIds与draftIds分开；跨页草稿不依赖候选页重建 |
| 角色定义/选权 | 分页列表、空角色新建、改名/启停、权限勾选 | 角色草稿与权限草稿独立，切换目标提示未保存修改 |
| 资源工作区 | RBAC目录、权限树、属性面板、API列表/映射 | 正式仅RBAC目录，完整草稿跨候选页保留；API候选只属于当前权限系统 |
| 日志 | 筛选、total、记录、继续加载/刷新 | snapshot筛选、cursor、limit和累积items绑定同一轮查询 |

HTTP客户端统一拼接/api、Bearer、JSON与响应信封，处理requestId及错误；组件不直接散落fetch或自行解释角色名。会话支撑先沿当前实现复核，不在本次设计中悄然引入JWT/刷新令牌；不在URL、控制台或埋点保存token/凭据。

## 7. 页面与接口协作

| 场景 | 读取/写入顺序 | 失败及权限变化 |
| --- | --- | --- |
| 登录后到达 | 登录→本人/本人权限→获准工作区必要查询 | 不能强制先读日志或全局目录导致部门账号卡死 |
| 展开人员授权 | 当前角色→受限候选分页→PUT整体ids→重读目标 | 查询/保存分别可能403；不可授已有角色不能被静默漏删 |
| 全局角色选权 | 角色列表/详情集合→按RBAC目录选权→PUT完整ids | 选父不选子，停用/未登记/未知项400，K冲突409；API映射仍须同系统 |
| 资源映射 | 读完整已保存映射→API候选分页→PUT完整ids | 停用API可保留但标明不贡献有效能力，取消不写 |
| 停用/调动 | 确认目标→PATCH false或PUT目标部门→重读列表 | 不乐观宣告成功，双范围403或K冲突后保留安全上下文 |
| 日志继续加载 | 初次筛选→绑定cursor继续→到底 | 修改筛选/limit清cursor；身份/权限变更终止旧请求 |

接口精确方法/路径与Schema见[API对照](api-map.md)及OpenAPI，不在组件说明重复定义字段。前端可以用实际请求结果决定获准操作，不新增未评审的“管理员资格”接口。正式页面依据GET /me返回的最新实际routes，不按固定code显示全部菜单；403刷新实际能力，弹窗禁用失效保存并保留草稿，人员列表重读目标writable。

## 8. 关键异常与可用性验收

每个工作区应演示加载、无数据、输入错误、403、404、409和网络故障；提交中禁重复写。切换账号、部门、目标或筛选时，旧响应不得覆盖新状态。整体替换失败不清空服务器结果或显示部分成功；重试前重新核对目标与草稿。

危险操作确认写清目标与影响，角色定义/资源改动说明共享影响；普通员工管理准入失败不进入管理空间。表单标签明确“工号或手机号”，错误区可读，焦点进入/退出对话框正确，键盘可完成筛选和确认，窄屏保留目标摘要与操作结果。

原型只能证明交互可讨论；正式验收须用真实HTTP验证部门范围、后端拒绝、跨页草稿、401切换、撤权即时生效及数据库最终状态。structured与ddd共用同一前端，分别执行相同行为场景，不复制两份页面。用户授权后已由当前[唯一原型](../prototype/README.md)替换旧四组及v2并行目录，历史版本从Git追溯；原型已获准并合入，正式实现交付仍须用户审核。

## 9. 正式实现边界

Vue页面只调用RBAC自身接口。原型演示的18业务系统、原表角色矩阵和模拟故障控制器不进入正式产品；课程管理系统暂不接入。部门增删改、总览、职位/角色摘要、固定授予级别和目标保护均沿OpenAPI及本设计实现。

CollectionEditor先读完整已保存集合，成功后才允许候选查询及保存；403/500/网络失败展示请求号和完整重试。候选目录失败不清空已选；系统目录失败后重试重新读取目录。跨候选页的勾选和已有不可授项独立保留，移除必须由用户操作。关闭弹窗和切换身份丢弃晚响应。日志条件及每批条数与当前快照绑定，在途修改条件后仍显示待查询并禁续旧快照。
