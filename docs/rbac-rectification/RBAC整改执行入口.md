## 基线与多人协作

- 整改共同基线：refactor/rbac-core-backend。PR #1 尚未合并至 main，现阶段 RBAC 整改优先按本页流程；CONTRIBUTING 中从 main 开始的通用示例不用于当前整改。
- 开工先读 Git 状态和远端分支，确认当前基线含本次执行资料。文档尚未推送时，本机可基于已提交的同名本地分支开始；其他机器须先取得同一文档提交。同步后优先使用最新远端整改基线。
- 每个执行对话使用独立工作分支，多个对话同时写代码时使用独立工作树。参考命名 task/t01-model-review；这里没有预先建立实现分支或工作树。
- 组员手动认领。用户在另一个对话明确指定 Txx 后，该对话只处理该票；技术阻塞尚未解除时先报告缺少的前置证据，继续完成本票允许的准备工作，不能跳过阻塞实现正式接口。
- 修改前核对该票的共享模块及冲突。T07/T09/T11 可以在各自前置完成后并行，但有效授权、AOP、初始化、事务与保护规则须协调，避免同时覆盖同一公共实现。
- 保留原始 Excel、原库和已有本地未跟踪的小组文档。按本次实际文件逐项暂存，保持无关改动在提交之外。
- 任务 PR 指向当前共同整改分支，描述引用 Txx；平台发布后补对应 Issue。合入非默认分支时，由评审者按验收证据维护完成状态，不依赖自动关票。
- 每票完成须有对应验收证据及小组评审结论，所需产物进入后续使用的基线后才解除阻塞。代理不能自行签署小组评审或自行合并。

## 范围规则

- 有效账号通过既有身份校验即可登录；无管理权限显示提示；管理请求按具体权限和部门范围校验。必要的旧身份衔接随业务迁移完成，不增加管理员属性、独立登录资格或新的认证功能。
- 保留可复用工程骨架，逐块替换错误模型与 JDBC 实现；旧功能清理覆盖调用、初始化、测试、配置和文档。
- 正式前端暂缓，原型仍要做。原型演示和后端通过不能宣称正式界面已经验收。
- T14/T15 为课程后续，须小组确认真实受控场景和启动范围；系统字段预留不是完成课程或双系统要求的证据。
