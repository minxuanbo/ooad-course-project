## 3. 方案建议与用户补充

以下内容有实现理由，但检查纪要没有逐项规定：角色全局共享、单部门归属、根部门人员维护全局角色资源、权限与 API 使用多对多、九张表、分页默认 20/最多 100、整体替换授权和停用替代删除。它们保留为本方案的简化默认值，不能表述成老师原话，也不据此认定课程正式要求 RBAC0。

防越权、事务回滚及最后有效管理员保护继续保留为必要防护，不扩展成审批、交接、日志平台等新模块。管理员始终需要实际管理权限，属于根部门本身不会自动取得管理权。

**本次采用的账号规则（用户补充）**：有效账号在既有身份校验通过后允许登录，不以管理权限作为登录条件。无管理权限时显示“当前账号暂无管理权限”提示；后端仍按具体操作权限和部门范围校验每个管理请求，越权请求拒绝。不增加管理员属性、独立登录资格或新的认证功能。这项规则是本次用户确认的方案，不冒充检查纪要原话。
