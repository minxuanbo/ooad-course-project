# 用户角色与管理范围演示方案

版本 4.0，2026-10-25。规则以 [API 设计](../课程设计/03-API设计文档.md) 为准。

## 权限分工

沿用五个预设角色，角色同时定义业务功能和管理操作；每位员工的角色范围独立保存。部长／副部长使用部门经理，项目经理／项目副经理／项目总工程师使用项目经理。无需新增独立的管理角色。

系统管理员可配置角色操作及员工角色范围，并查看全平台鉴权日志。公司领导、部门经理、项目经理默认可查询人员、受限分配角色、查看角色／组织／系统目录、发起和完成离职；公司领导默认另有组织维护。部门和项目角色默认无组织维护权。

## 原型演示步骤

在系统管理员身份下给某员工分配部门经理角色，在管理范围区添加“总公司—综合办公室”。另一员工可同角色管理不同部门；兼管者添加多条范围。保存后切换对应示例身份，检查列表和组织。

将该角色的范围改为公司，只需选公司，覆盖公司全部部门。全平台仅用于系统管理员，无公司部门字段。撤销角色自动撤销该角色范围；只撤范围不撤业务功能权限。取消弹窗不保存任何草稿。

角色页面修改“管理操作权限”影响该角色全部持有者；员工页只修改该人的角色分配和范围。日志仅有效系统管理员可见。普通员工只有我的应用。

## 真实接口验证

验证专用演示账号的公司过滤、跨公司空结果、精确部门、多范围、越权拒绝和同会话撤权；验证结束恢复该演示账号原有角色和范围。不为演示修改真实员工或共享角色定义。

后端集成测试在独立 MySQL 验证角色权限替换影响所有持有者、权限与范围必须同角色匹配、最后管理员保护、离职撤权及事务回滚。参见 [测试报告](../测试/08-实施与测试报告.md)。

## 边界

本权限平台管理范围不等于外部业务系统的数据范围。当前没有通用用户／角色 CRUD、人员组织迁移、密码重置、HR 持续同步、OA 自动审批或角色继承；不可在演示中声称已经实现。
