# 离线交互原型 · 第二轮

2026-11-13；分支codex/interactive-prototype。基于已合入的PR #30，按用户第一轮反馈扩展；界面仍在评审中，尚未成为正式frontend。

## 直接打开

用现代Edge或Chrome双击[index.html](index.html)，无需启动服务、安装依赖、构建或连接后端。分发时保留同目录六个文件：index.html、styles.css、catalog.js、model.js、pages.js、app.js。普通脚本按顺序加载，不用ES Module、接口请求、远端字体/CDN或浏览器存储。刷新、重置后还原演示数据。

全部为虚构演示数据：168名人员、15个组织节点及少量分页角色；不是原Excel人员，也不代表正式10001账号/110部门初始化。演示口令Demo@2026不能用于正式环境。

| 身份 | 账号 | 可见工作区 |
| --- | --- | --- |
| 系统管理员 | admin | 总览、部门管理、人员管理、角色与权限、资源与API、鉴权日志 |
| 公司领导 | SG000001或13800000001 | 第一分公司范围总览、人员管理 |

## 本轮改动

1. 总览：范围内人员/启用/停用/组织数量，下级人员分布及获准快捷入口；仅日志获准的共同根用户看到最近鉴权活动。
2. 部门管理：仅系统管理员在共同根修改名称，保留ID、层级、人员归属和角色；同级重名/空名反馈错误，无新增/删除/调整层级。
3. 人员管理：独立显示只读“职位”和“已授角色”；职位来自人事资料，不提供编辑或职位调动。角色摘要包括停用项，分配时仍独立读取完整集合。
4. 授予级别：系统管理员全部；公司领导本级及以下；部门经理为部门经理/项目经理/普通员工；项目经理为项目经理/普通员工。仍检查实际Permission子集及人员范围，不能按相同API能力越级。
5. 自定义角色默认仅系统管理员可授；名称修改不改变级别，其持有者不会自动成为管理员。角色新建为空权限，随后显式独立选权，无继承或删除。
6. 资源：菜单/按钮树、父级/类型/状态、API启停和完整API映射；方法/路径/编码/系统只读。停用API可保留映射；父菜单不自动授予子项。
7. 日志：组合筛选、同快照total、分批加载、刷新及脱敏详情；鉴权允许与后续400/404/409/500业务响应分别记录。没有归档、导出或按日汇总报表。

全部导航按有效操作和共同根范围显示，级别用固定元数据约束角色授予，不用角色名称判断操作权限。完整维护者同时需要同一启用共同根用户覆盖K及拥有恢复基础管理员角色的授予级别；原型用内存回滚演示，不冒称真实事务锁。

## 建议体验

- admin登录，查看总览全部入口；把“滨江项目部”改名，再到人员页和总览核对同步。
- 人员页查看沈清禾SG000004的职位/角色；分配抽屉跨页选择、取消/放弃、清空确认及保存；职位始终只读。
- 切到项目经理，候选只出现项目经理和普通员工；切到部门经理看三级边界；各身份组织树保持本人范围。
- 角色页新建自定义角色，再配置权限；只勾选父菜单不会自动选子权限。
- 尝试撤去管理员关键权限、停用关键API或清空关键映射，观察LAST_ADMIN_REQUIRED及草稿/数据回滚。
- 日志加载下一批，total与snapshot保持；修改筛选后须重新查询，不能将新条件串到旧游标。
- “原型评审”可模拟下一次读取/保存的网络、401/403/404/409/500错误，切换身份、慢加载、撤权或重置。该工具属于评审辅助，不进入正式产品。

## 与正式接口的差异

现有OpenAPI的角色、资源、人员写及日志接口维持原样。下列是用户新增需求的后续接口/模型设计待办，**当前没有修改正式OpenAPI、后端或物理表**：

| 新需求 | 后续需落实 |
| --- | --- |
| 职位与角色摘要 | 人员列表增加position及轻量roles摘要，保留人员范围；避免逐行N+1。职位源已有User.position，来源Excel“岗位”，不加编辑接口。 |
| 授予级别 | Role增加稳定级别元数据及默认自定义授予策略；候选/整体保存和最后维护者恢复条件统一落实。不根据名称/职位推断。 |
| 部门改名 | 独立部门目录与PATCH名称操作、管理员有效权限及可信共同根校验；原型路径为GET /api/departments与PATCH /api/departments/{id}的设计提案。 |
| 总览 | 确定范围内聚合查询契约或复用查询方案，权限/范围在服务端执行；不从全量人员前端计数。 |

原型满意后，再统一评审Schema、错误、约束及数据库迁移，随后进行正式实现和真实联调。本轮模拟方法不是后端接口证据，演示路径不应混入当前OpenAPI。

## 文件与检查

- catalog.js：虚构权限/资源目录。
- model.js：内存身份、范围、级别、角色/资源、快照日志与回滚。
- pages.js：总览、部门、角色、资源、日志页面与交互。
- app.js：共用外壳、登录、人员及模态/请求状态。
- tests：离线加载、既有行为及本轮新需求检查。

在仓库根执行：

```text
node --check prototype/v2/app.js
node --check prototype/v2/pages.js
node --check prototype/v2/model.js
node --check prototype/v2/catalog.js
node --test prototype/v2/tests/*.test.cjs
```

真实浏览器检查与审核记录见[原型评审](../../docs/prototype-review.md)。用户满意前，不自行合并或启动正式前端/DDD/服务器部署。
